# ShotMap AI 영상 시험 계획과 정답표

## 1. 문서 목적

AI 결과가 맞는지 판단하려면 사람이 먼저 영상의 정답을 기록해야 합니다. 이 문서는 개발용 샘플 영상과 직접 촬영 영상의 사용 범위, 정답 기록 방법과 정확도 계산 방식을 정합니다.

## 3. 직접 촬영 권장 조건

- 가로 화면
- MP4
- 최소 1080p
- 가능하면 60fps
- 카메라 고정
- 반코트 전체, 골대, 림과 주요 코트 선이 계속 보임
- 선수 발과 전신이 가능한 한 보임
- 촬영 중 확대·축소와 좌우 회전 없음
- 다른 사람이 나오면 촬영과 분석 동의를 얻음

## 4. 직접 촬영 영상에 넣을 장면

### 1분 영상

- 5~10개 정도의 슛
- 성공과 실패가 모두 포함
- 최소 두 곳 이상의 슛 위치
- 제자리 슛과 드리블 풀업 포함
- 가능하면 레이업 한 개 이상 포함

### 10분 영상

- 슛을 하지 않는 이동과 공 줍기 장면 포함
- 여러 코트 구역에서 슛
- 성공과 실패가 섞임
- 제자리, 풀업, 레이업과 가능한 다른 슛 종류 포함
- 영상 처음과 끝에 가까운 슛 포함
- 분석을 취소하고 다시 시도할 수 있는 충분한 길이

## 5. 정답표 작성 규칙

- 영상 시간은 가능하면 0.1초 단위로 기록합니다.
- 슛 준비 시작부터 결과 확인까지를 한 시퀀스로 기록합니다.
- 슛 위치는 슛을 놓는 순간 선수 발의 가운데를 기준으로 합니다.
- 림을 통과하면 성공, 통과하지 않으면 실패입니다.
- 슛 종류가 애매하면 억지로 정하지 않고 `확인 필요`로 기록합니다.
- 한 동작을 두 슛으로 중복 기록하지 않습니다.
- 공을 던졌지만 슛 의도가 아닌 패스는 슛으로 기록하지 않습니다.

## 11. 정확도 계산

### 슛 발견률

`프로그램이 올바르게 찾은 실제 슛 수 ÷ 실제 슛 수 × 100`

목표는 개인 연습 영상에서 80% 이상입니다.

### 잘못 추가한 슛

실제로는 슛이 아닌데 프로그램이 슛으로 만든 기록 수를 별도로 셉니다. 발견률이 높아도 잘못 추가한 슛이 많으면 좋은 결과로 보지 않습니다.

### 성공·실패 정확도

`성공·실패를 맞힌 슛 수 ÷ 프로그램이 올바르게 찾은 슛 수 × 100`

목표는 85% 이상입니다.

### 위치 정확도

- 예상한 14개 구역과 프로그램 구역이 같은지 기록합니다.
- 정확한 좌표 오차도 측정할 수 있으면 함께 기록합니다.
- 코트 선이 충분히 보이지 않는 YouTube 샘플 B는 공식 위치 정확도에 사용하지 않습니다.

### 슛 종류 정확도

- 종류별 맞은 수와 틀린 수를 기록합니다.
- `기타`와 `확인 필요` 비율도 함께 기록합니다.
- 스텝백·턴어라운드·훅슛은 Phase 8 결과를 보고 필수 여부를 판단합니다.

## 14-0. Phase 7 실제 영상 시연 점검 (2026-10-29)

### 기존 영상으로 정답 대조 (2026-10-29)

- 대상: 샘플 B 원본 590~625초(35초, 60fps, 선수 1명). 원본 전체는 앱의 10분 제한보다 길어서, 구간 분석 함수에 시작·끝 시간을 지정해 시험했습니다. 프레임을 직접 확인한 슛은 위 표의 5개입니다. 현재 YOLO 모델은 **같은 영상의 575~625초로 학습**했으므로, 이 결과는 새 촬영 영상에서의 일반화 성능이 아닙니다.
- 설정: `basketball-yolo26n-pilot-v3.pt`, 원본 1920×1080·60fps, 분석 설정 8fps(실제 추출 7.5fps), 첫 구도 림 중심 [1494, 171]픽셀. 사람이 적은 릴리스 시점과 ±0.5초 이내 후보를 같은 슛으로 대조했습니다.
- 앱과 같은 단일 골대 기준점으로 분석: 263프레임, 약 61초 처리. 후보 5개 중 실제 슛 2개(591.467초, 601.333초), 잘못 잡은 동작 3개(597.867초 드리블, 604.533초 리바운드, 622.267초 드리블), 놓친 슛 3개입니다. 이 35초의 슛 발견률은 **2/5=40%**, 후보 적중률은 **2/5=40%**입니다. 카메라 구도 전환 프레임 99개를 표시했습니다.
- 두 번째 화면 구도인 607~620초를 사람 손으로 림 중심 [565, 334]픽셀에 다시 맞춰 별도 분석: 98프레임, 약 20초 처리. 실제 슛 2개를 모두 찾았으나 걷기·공 줍기에서 후보 2개가 추가됐습니다. 이 진단은 구간과 림을 사람이 다시 지정한 결과이며, 현재 앱의 단일 분석 결과에 합산하지 않습니다.
- 모델 학습에 쓰이지 않은 같은 영상의 626~641초(15초, 선수 1명, 슛 없음)를 별도로 분석: 113프레임, 약 31초 처리. 걷거나 설명하는 장면에서 **잘못된 슛 후보 3개**(632.400초, 635.467초, 640.800초)가 나왔습니다. 슛이 없는 구간의 오탐도 줄여야 합니다.
- 후보에 저장된 발의 **화면 픽셀 좌표**는 확인했지만, 영상에는 코트의 실제 기준 거리와 안정된 바닥 기준점이 부족해 14개 구역 또는 실제 거리의 위치 오차를 계산하지 않았습니다. 두 번째 슛 후보의 발 y좌표는 화면 경계인 1080픽셀이어서 위치를 확정하기 어렵습니다.
- 샘플 A도 10~92초를 장면 표본으로 확인했습니다. 가까운 얼굴 화면, 드리블 장면, 골대만 보이는 화면이 자주 교차해 선수와 골대가 같은 고정 구도에 계속 잡히지 않습니다. 따라서 이번 후보 시점의 정량 비교는 샘플 B의 위 구간으로 진행했습니다.
- 판정: 기존 영상으로 **Phase 7의 탐색적 정확도 검사는 가능하고 실제로 진행했습니다.** 현재 결과는 80% 발견률 목표를 입증하지 못하며 오탐도 많습니다. 구도 전환 자동 처리, 드리블·리바운드 억제, 화면 밖 발 위치 경고를 먼저 개선해야 합니다. 새 촬영 영상에서의 공식 합격 판정은 별도로 남습니다.

- 샘플 B에서 590~595초의 실제 코트 장면을 5초짜리 로컬 시험 영상으로 만들었습니다. 원본 60fps를 이 시험용 파일에서는 30fps로 줄였으며, 서비스가 원본 fps를 그대로 기록하는지 확인했습니다.
- Chrome에서 영상의 림 중심을 사람이 옮겼습니다. 초기 골대 표시는 실제 림에서 화면상 약 150픽셀 떨어져 있었고, 옮긴 뒤 표시 중심은 눈으로 본 림 중심과 약 20픽셀 이내였습니다. 바닥 네 점은 공식 코트 정답이 없어 대략적인 점으로만 저장했습니다.
- 이 5초 영상에서 4fps 분석은 후보 0개, 8fps 분석은 약 1.5초에 후보 1개를 찾았습니다. 사람이 0.8초, 1.47초, 2.0초 프레임을 확인했을 때 이 장면은 실제 슛 준비와 릴리스였습니다. 8fps를 기본값으로 바꿨습니다.
- 실제 작업을 시작 직후 취소했을 때 상태가 `canceled`, 처리 구간이 0초, 후보 조회는 404가 되었고 원본 MP4는 남았습니다. 다시 시작하면 후보 1개가 복구되고, Chrome 화면에도 1.5초 후보가 표시됐습니다.
- 샘플 B 590~625초를 4fps로 분석한 첫 결과는 6개 후보였지만 중간의 다른 카메라 구도에서 드리블을 슛으로 잘못 잡았습니다. 림 위치가 크게 달라지면 코트 기준점을 무효로 처리한 뒤 같은 구간의 후보가 3개가 됐습니다. 이 3개도 사람이 작성한 전체 정답표와 비교한 공식 정확도는 아닙니다.
- 여러 선수 화면에서 3대3 형태로 두 명을 추가하고 서로 다른 화면 위치를 지정한 뒤 새로고침해 두 위치가 유지되는 것을 확인했습니다. 이 시험 영상에는 실제 선수가 한 명뿐이므로 선수 사이를 자동으로 구분하는 정확도는 검증하지 못했습니다.
- 화면 폭이 좁을 때 영상이 너무 작아지는 문제와 전신보다 짧은 기본 선수 상자를 발견해 배치와 기본 높이를 조정했습니다. 저장된 코트 기준점을 다시 열면 초기 점으로 되돌아오는 문제도 고쳤습니다.
- 기존 샘플 영상의 35초 정답 대조는 위에 기록했습니다. 발표용 공식 정확도 판정에는 선수가 한 명인 고정 카메라 영상과 실제 슛 시점·발 위치 정답표가 여전히 필요합니다. 여러 명의 자동 구분 검증은 Phase 13 이후로 미룹니다.
