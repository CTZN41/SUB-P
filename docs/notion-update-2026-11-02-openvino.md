## 진행사항에 추가

### Phase 14 — 로컬 슛 후보 속도 개선

- 10분 전체 분석은 사용자가 취소했다. 같은 파일의 앞 3분을 기존 방식과 OpenVINO CPU·GPU로 각각 비교했다.
- PyTorch CPU는 168.7초, OpenVINO CPU는 83.2초, Intel 내장 GPU는 170.4초였다. 이 PC에서는 OpenVINO CPU가 가장 빨랐다.
- OpenVINO CPU에서도 앞 3분의 후보 27개 시각과 발 좌표가 모두 같았다. 별도의 짧은 영상 6개에서도 기존 후보 11개가 모두 같은 시각·좌표로 유지됐다. 짧은 영상 합계 처리 시간은 77.8초에서 40.0초로 줄었다.
- 현재 PC는 OpenVINO CPU를 사용하도록 설정했다. 기존 학습 가중치는 그대로 보존하고 실행 형식만 FP32로 변환했다. 재탐지도 같은 실행 장치를 사용하도록 연결했다.
- DB 진행 상태 조회·저장을 실제 시간 간격으로 제한했다. 진행 화면에는 경과 시간·총 소요 시간·후보 탐지 시간을 추가하고, 전체 분석 버튼에는 유료 AI 포함을 표시했다.
- 백엔드 자동 시험 144개와 프론트 빌드가 통과했다. 두 서버를 재실행했고 8000 health·5173 홈은 HTTP 200이었다. 이번 후보 속도 시험에서 OpenAI 호출과 입력·출력 토큰은 모두 0이다.
- 전체 영상의 90~100% 정확도를 입증한 것은 아니다. Phase 14의 독립 정답표·다른 구역 정확도 검증은 남아 있다. Supabase 전체 작업에서 DB 대기 개선 효과도 별도로 측정해야 한다.

## 발전 방향에 추가

### 문제에서 개선까지 — 후보 탐지 실행 방식

1. 문제: 약 10분 영상을 처리할 때 후보 탐지가 오래 걸렸다. 코드가 CPU에서 객체·자세 모델을 순차 실행하고 일부 프레임은 고해상도로 한 번 더 검사하며, DB 상태 접근도 자주 수행하는 것을 확인했다.
2. 측정: 영상 읽기, 객체 탐지 640·960, 자세 탐지, 취소·진행 콜백 시간을 구분해 기록하도록 만들었다. 검사 프레임 수를 줄이지 않고 실행 방식을 먼저 비교했다.
3. 비교: 동일 가중치·동일 앞 180초에서 PyTorch CPU 168.7초 → OpenVINO CPU 83.2초로 50.68% 단축됐다. GPU는 170.4초여서 선택하지 않았다.
4. 정확도 보존 확인: 후보 27개 시각·발 좌표가 기존과 같았다. 실내 27초, 야외 18초, 개인 22초, Mixkit 2278·44448, Pexels 5191594 등 여섯 짧은 영상에서도 11개 후보가 동일했다. 짧은 영상 합계 시간은 48.56% 감소했다.
5. 채택: OpenVINO CPU와 같은 가중치의 FP32 변환 모델을 사용한다. 재학습이나 새 데이터 추가로 정확도가 향상됐다는 의미가 아니라 실행 속도를 개선하면서 기존 후보를 보존한 것이다.
6. 한계와 다음 검증: 앞 3분의 실제 정답 슛 개수는 독립 판독하지 않았다. 기존 결과와의 일치율을 전체 슛 정확도로 표현하지 않는다. DB 변경의 실제 Supabase 전후 시간, 다른 촬영 구도·경계 구역 정확도와 발표 환경을 추가 검증한다. 이번 비교는 유료 AI 단계까지 진행하지 않았다.
