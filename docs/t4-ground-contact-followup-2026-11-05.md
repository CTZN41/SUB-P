## 확인한 원인과 변경

### 실제 검은 자유투선

기존 검사는 밝은 픽셀만 찾았다. 검은 선도 주변 밝기 대비와 선 두께·길이·직선 잔차를 검사하도록 확장했다. 얇은 바닥 이음새·균일한 밝은 바닥·넓은 그림자는 합성 반례로 제외했다.

중간 안내에서 바닥 이음새 검출 가능성을 제기했으나, 원본 픽셀을 다시 확인해 현재 검출선이 실제 검은 페인트 선과 일치함을 확인했다. 사용자는 저장3·4번 점이 실제 자유투선 끝과 맞다고 확인했다. 저장 기준점은 그대로 사용했다. 최종 판정은 실제 관측된 선을 사용한다. 선이 없을 때 수동 환산선으로 대체하는 실험 경로는 최종 코드에 포함하지 않았다.

### 공중에 뜨지 않는 슛

T4 뒤쪽 세 슛은 발을 둔 채 뒤꿈치를 들어 던진다. 점프의 공중 프레임을 필수로 요구하던 검사가 이 자세를 보류했다. 릴리스 기준 -600~+150ms 원본 장면과 릴리스 전체 화면을 제공하고, 실제 점프와 발을 둔 릴리스를 구분한다.

슛 검증90% 이상과 제자리 슛 판정이 있고, 릴리스 전후 모든 요구 프레임에서 두 발의 접지와 구도가 확인돼야 발을 둔 릴리스 경로를 사용한다. 접촉점 위치가 가려지는 뒤꿈치 들기 구간에서는 별도로 두 신발의 수평 위치가 그대로라는 판단70% 이상이 필요하다.

동일 위치가 확인되면 입력 범위600ms 안에서 연속3프레임·60ms 이상의 접촉점 묶음을 고른다. 기준은 밑창 측정 신뢰도, 픽셀 오차, 최신 시각 순서다. 이 선택은 구역의 안팎 값을 보지 않는다. 선택 뒤 기존 선 경계·오차·코트 범위와 좌표 안정성을 검사한다. 신뢰도는 실제 측정값과 발 위치 유지 판단의 최솟값을 사용한다. 같은 품질 이상의 경계 걸침이나 양쪽 판정 충돌은 계속 보류한다.

### 릴리스 시간이 빈 응답

중간 전체 시험의56.4초 후보는 슛99%였지만 release_offset_ms가 null이었다. 설명에는 릴리스가 +200~+500ms 사이라고 적혔다. 시간값이 없으니 원래 후보 시각을 사용했고, 신발 묶음이 실제 릴리스 전에 끝났다.

슛이 확인됐고 시간값만 빈 경우에는 호출 한도가 남을 때 한 번만 -600~+900ms를100ms 간격으로 재검토한다. 실제 제공한 프레임의 시간값·슛90% 이상만 채택한다. 새로운 시간을 만들거나 실패 때문에 확인된 슛을 버리지 않는다. 장면 경계를 지키며 기존 요청 재사용과 토큰 집계를 사용한다.

별도 실제 요청은 +300ms를 반환했다. 최종 전체 작업에서도 이 분기가 실행돼56.400→56.700초로 보정됐고, 새 시각의 발 궤적과 접지 위치를 확보했다. 일반 시각이 있는 후보에는 이 호출을 추가하지 않는다.
