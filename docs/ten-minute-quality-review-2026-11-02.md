# 10분 분석 결과 품질 검토

검토일: 2026-11-02. 대상: `0d2290c6-1bdb-4918-b21a-354454a133a2`, 599.05초 영상. 기존 코드로 완료된 결과를 읽기 전용으로 검토했다. 새 분석·유료 API 호출·기존 기록 수정·삭제는 하지 않았다.

## 판단

**영상을 먼저 분석한 뒤 사람이 확인하는 시험용 도구로는 사용할 수 있다. 사람이 확인하지 않고 10분 전체의 정확한 슈팅 통계를 얻는 용도로는 아직 부족하다.** 처리 시간이 41분 11초이고, 실제 슛 누락과 실패를 성공으로 자동 확정한 사례가 있으며, 종류·위치의 반복 일관성도 부족하다.

이번 영상은 약 100초를 여섯 번 반복한 부하 시험 파일이다. 반복 전의 구간에도 자막, 편집과 약 88초의 화각 변화가 있다. 따라서 10분 동안 촬영한 무편집 원본의 정확도 시험과 구분한다. 같은 장면 반복을 독립적인 84개 정답 사례로 홍보하거나 일반 정확도로 사용하지 않는다.

Chrome의 결과 요약에서 86·69/9·확인 필요18을 확인했다. 기록 관리를 열어 62.20초 후보를 선택하자 원본 플레이어, 확인 사유와 수정 영역이 표시됐다. 저장·삭제·분석 재실행은 누르지 않았다. 접근성 정보에는 3D 표시 대상이 68개로 나온다. 이번 시각 스크린샷 캡처는 도구 시간 초과로 실패했으므로 캔버스의 실제 68개 마커를 눈으로 하나씩 확인했다고 주장하지 않는다.

화면의 **88.5%는 모델 정확도가 아니다.** 판단된 득점 기록의 성공률 `69 / (69+9)`이다. 위치 확인 필요 기록 중에도 성공·실패가 정해진 경우가 있어 18과 8은 다른 수치다.

### 실제 슛 누락과 이른 후보

- 약 **406.0·411.2·492.6·506.0초**에서 팔로스루 또는 공 릴리스가 보이지만 ±1.5초 이내 저장 후보가 없다. 앞 반복에는 대응 후보가 있다. 후보가 없으므로 확인 필요 목록에도 올라오지 않는다.
- 약 511.2초에도 실제 슛이 있다. 가까운 509.932초 후보는 실제 동작보다 약 1.3초 이르고 `not_shot`으로 보류됐다. 보류 결과만으로 실제 슛이 없었다고 처리하면 놓친다.
- 마지막 598.349초 슛은 후보로 보존됐으나 상세 처리 실패다. 원본도 599.05초에 끝나므로 득점이 마무리되는 장면이 충분하지 않다. 이것이 실제 API 예외의 원인인지는 로그가 없어 단정할 수 없다.

## 이번 반복 파일의 조건부 수치

첫 구간의 14개 릴리스에 매 100초를 더해 대응 시도를 만들고 ±1.5초의 일대일 근접 비교를 했다. 이미지로 후반 네 누락 장면과 같은 실패 슛의 반복 장면을 추가 확인했다.

- 대응 시도 84개 중 저장 후보 대응 **80개(95.2%)**, 후보 없음 4개. 이 80개에는 실제 슛보다 이른 509.932초와 최종 처리 실패도 포함된다.
- 원본 끝에서 득점이 마무리되지 않은 마지막 시도 1개를 제외하면 득점 대조 대상 83개다. 득점값이 정해진 78개 중 일치 75개 / 불일치 3개다. **75/78=96.2%는 이미 판정된 기록만의 조건부 일치율**이며 누락·보류를 제외한다.
- 누락·보류까지 포함해 득점 대조 83개 중 맞는 값이 저장된 것은 **75개(90.4%)**다. 위치나 종류까지 모두 맞았다는 뜻은 아니다.
- 독립적인 실영상 정답 84건을 확인한 시험이 아니라 같은 14개 장면의 반복 비교다. 따라서 위 수치를 서비스 전체 정확도나 다른 영상에서의 보장값으로 사용하지 않는다.

## 코트와 골대 설정의 문제

저장된 19.5초 기준 프레임에 4개 점과 골대 점을 겹쳐 확인했다. 바닥 4개 점은 페인트존 모서리에 가깝게 놓여 있으나 독립 실측한 값은 아니다. **골대 점은 림 중심보다 위쪽 백보드에 놓여 있다.** 4개 바닥 점과 별도의 골대 점을 각각 확인해야 한다.

약 88초에서 화면 구도가 확대된 장면으로 전환되지만, 결과는 공통 카메라 장면 1개를 사용했다. 이전 기준점 투영을 그대로 쓰면 후기 위치에 오차가 생길 수 있다. 동적 골대 추적도 있으므로 잘못된 골대 초기점 하나가 모든 누락·위치 오류의 단독 원인이라고 단정하지 않는다.

구역별 독립 정답 좌표를 아직 만들지 않았으므로 14개 구역 정확도는 숫자로 보고하지 않는다. 이번 저장 좌표를 수정하거나 재분석하지 않았다.

## 실사용 판단과 다음 우선순위

| 용도 | 판단 |
|---|---|
| 발표에서 분석·3D·히트맵·검토 흐름 시연 | 가능. 틀린 자동 판정과 반복 시험의 한계를 함께 설명해야 함 |
| 개인이 결과 영상을 보며 수정하는 보조 기록 | 조건부 가능. 검토 18개뿐 아니라 자동 기록과 후보가 없는 구간도 표본 확인 필요 |
| 사람이 보지 않는 완전 자동 통계 | 아직 부족. 자동 성공 오판·누락·종류/구역 불일치 존재 |
| 무편집 10분·1시간 영상의 정확도 보장 | 미검증. 이번 반복·편집 영상에서 확장해 말할 수 없음 |

1. **득점 오판부터 재현·수정**: 57초/157초/257초/457초 장면의 실제 전달 프레임과 추가 득점 응답을 비교한다. 림 통과와 림 바깥 낙하를 구분하는 근거가 없는 성공 확정을 줄인다. 단순히 성공/실패 임계값만 낮추지 않는다.
2. **후반 후보 누락과 이른 후보 원인 분리**: 406·411·493·506·511초에서 YOLO 공·선수 궤적, 후보 생성·병합·AI 시각 보정 중 어디서 탈락했는지 확인한다. 존재하는 후보만 재검토하는 것으로 해결되지 않는다.
3. **골대 초기점과 화각 변화 검증**: 기존 기록을 바꾸지 않는 새 시험에서 실제 림 중심을 맞추고, 확대 전후를 분리해 위치를 비교한다. 동일 기준점을 모든 편집 장면에 적용하지 않는다.
4. **별도 시험한 두 후보 동시 처리와 상세 계측**: 정확도 회귀를 먼저 고정한 뒤 전체 처리 시간을 줄인다. 37%의 소규모 기본 호출 단축을 전체 41분의 보장 개선율로 계산하지 않는다.
5. **검토 화면 가독성**: 확인 필요 18개를 바로 모아보기, 원시 `needs_review` 한글화, 자동 판정과 확인 필요 사유의 명확한 구분을 검토한다. 이번 작업에서는 UI를 변경하지 않았다.

증거 자료: 실험본 `backend/work/ten-minute-audit`의 전체 장면 5장, 림 주변 연속 프레임 15장, 기준점 겹침 이미지, 후반 반복 확인 이미지, `label-comparison.json`. 이 자료는 로컬 시험 산출물이며 원본·비밀값·전체 채팅을 Git이나 외부 서비스에 올리지 않았다.
