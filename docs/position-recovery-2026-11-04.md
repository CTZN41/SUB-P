# 2026-11-04 위치·후보 복구와 단계별 고정 구간

## 범위와 보존

대상은 `cb49b783-591d-4999-a131-286d6ee80b54`의 10분·30슛 반복 시험이다. 기존 저장 결과·슛 DB·원본 영상은 수정하지 않았다. 로컬 재탐지, 기존 응답 재현, 필요한 위치/슛 여부만 Terra 5회로 시험했다. 10분 전체 유료 분석을 다시 돌린 결과가 아니며 결과 화면의 기존 22/4/3/1 집계는 유지한다.

## 구현한 네 가지

1. **실제 위치 표시:** 3D 겹침 펼침과 마커 중심의 경계 보정을 제거했다. 26번의 저장 좌표 `(11.3,19.5)`를 표시 단계에서 약 0.85m 옮기던 동작이 사라진다. 겹침은 그대로 유지하며 선택·필터·번호 때문에 중심이 달라지지 않는다.
2. **릴리스 보정 뒤 접지 재확보:** 보정된 시각 주변을 15fps로 다시 탐지하고 발 궤적에 원래 시각을 유지한다. 고정 ‘릴리스 400ms 전’ 대신 발목 자세가 연속으로 안정적인 시각을 찾는다. 발목 자체는 신발 바닥보다 높기 때문에 발목을 직접 바닥 좌표로 투영하지 않는다. 선택한 시각의 사람 상자 하단은 보조 환산값으로만 쓰고 실제 신발 원본 확대 장면도 제공한다. 신발 잘림·자세 근거 부족은 숫자를 채우지 않는다. 자동 확정 기준 70%는 유지했다.
3. **좌표 없는 응답도 추가 검토:** 최초 좌표가 null이어도 신발 이미지가 있으면 영상 단독 3점 검토를 실행한다. 두 개 이상의 실제 제공된 접지 시각과 70% 이상 근거를 요구한다. 해결되지 않으면 숫자 재검토를 생략하고 보류한다. 영상 단독 판단과 숫자 위치가 충돌하면 자동 확정하지 않는다.
4. **준비 드리블·누락 추적:** 비슛 98% 이상·상세 단계도 비슛·같은 장면·같은 선수의 움직임 연결·뒤의 실제 슛 확인을 모두 만족하는 준비 드리블을 집계에서 제외하고 별도 감사 목록에 보존한다. 공 궤적/림 근거가 모자라 탈락하는 후보는 단계별 원인 기록을 남긴다. 다른 장면의 후보가 후속 합치기 단계에서 섞이는 경로도 차단했다.

## 각 단계별 고정 범위

설정은 `backend/app/analysis/candidate_windows.py`의 `WINDOW_RULES`에서 단계별로 독립 관리한다. 지금은 UI에서 직접 조절하는 기능을 추가하지 않았다. 같은 길이를 쓰는 두 재탐지도 기준 시각은 서로 다르다.

| 단계 | 기준 시각 | 고정 상대 범위 |
|---|---|---|
| 최초 YOLO 탐지 | 사용자가 올린 영상의 시작 | 선택 영상 전체, 내부 처리 단위의 앞 문맥은 3초 |

| 슛 여부 AI | 현재 후보 시각 | -1.4초 ~ +0.9초 |

범위가 다르게 보이는 예외는 명시적이다. 영상/선택 구간의 시작·끝에서는 존재하는 부분만 사용하고, 겹치는 로컬 재탐지 창은 합집합으로 합쳐 중복 처리를 줄인다. YOLO 탐지에는 앞쪽 3초의 디코딩 문맥이 별도로 있어 요청 범위와 디코딩 시작 시각이 다르다. 접지 확대에는 선택된 안정 시각의 원본 한 장을 추가할 수 있다. 이 문맥과 확대 기준은 새 슛의 집계 시각 범위를 늘리는 기능이 아니다. 실제 요청/적용 시각·경계 잘림과 규칙 탈락 원인을 결과 JSON에 남긴다.
