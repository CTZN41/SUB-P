## 1. 실패를 성공으로 자동 확정한 원인과 개선

원래 157.481·257.483·457.689초의 기본 판정은 실제 림 통과 대신 ‘공이 림 아래에 보임’을 근거로 성공을 반환했다. **원래 득점 전용 재확인의 조건은 신뢰도 기준이 아니라 결과가 `unclear`인 경우뿐**이었다. 기본 판단이 성공이면 신뢰도 68~70%여도 득점 전용 검토로 가지 않았다. 낮은 신뢰도에 대한 일반 모델 대체 조건과 득점 전용 조건을 구분해야 한다.

실험본은 다음 두 방식을 준비했다.

- 성공에 림 통과 근거가 없거나 실패에 림 바깥 반사 근거가 없으면 추가 득점 확인으로 보낸다. 공이 아래에 있다는 근거만으로 성공을 확정하지 않는다.
- 기본 전체 화면 15장·선수 크롭 7장을 유지하고 림 주변 8장을 추가한다. 같은 Terra가 처음부터 득점을 직접 볼 수 있도록 하고, 충분한 근거가 나온 후보는 2차 호출을 생략한다.

실제 API 결과:

| 시험 | 결과 |
|---|---|
| 기존 오판 3건을 득점 전용으로 재확인 | 기존 입력 방식과 새 입력 방식 모두 3건 실패로 바로잡음 |

이 6건은 오판 세 건과 대조 세 건으로 의도적으로 고른 작은 시험이다. 다양한 영상 전체의 공식 정확도가 아니며, 슛 종류·구역의 독립 정답률까지 100%라는 뜻도 아니다.

조건만 강화하면 기존 10분 결과의 재확인 대상은 22건에서 67건으로 늘어난다. 따라서 ‘재확인만 무조건 늘리는 방법’을 속도 개선으로 채택하지 않는다. 첫 입력의 림 근거 보강과 필요한 경우의 추가 검토를 함께 비교한다.

## 2. 후반 누락과 이른 후보

기존 첫 집중 재탐지는 기본적으로 앞의 네 구간만 선택했다. 406·411·493·506초 주변에는 신뢰도 0.5 이상의 자세 단서가 남아 있었지만 검사 범위에 들지 못했다. 실험본은 길이에 따라 최대 검사 구간을 늘리고, 제한해야 할 때에도 영상 전체에 분산한다. 거절 후보의 추가 재탐지 한도도 영상 길이에 맞춘다. 모든 후보의 기본 슛 여부 API는 독립적으로 두 개씩 처리하되 시각 보정과 중복 검사는 순서대로 적용한다.

| 원래 누락 근사 시각 | 30fps 재탐지 후보 | 별도 Terra 슛 여부 |
|---:|---:|---|
| 406.0초 | 405.662초 | 슛·신뢰도 0.99 |
| 411.2초 | 411.747초 | 슛·신뢰도 0.99 |

재확인 대조로 62.195초는 여전히 `not_shot`·0.98이었다. 이후 시각 오프셋 보정은 별도 값으로 저장하며 위 후보 시각을 정확한 릴리스 정답으로 간주하지 않는다.

509.932초 주변은 기존과 같은 끝 범위 `+2초`에서도 후보 511.666초가 나왔고 `+3.5초`에서는 511.766초였다. 따라서 창 확장만이 해결책은 아니다. 한도에 도달해 뒤의 후보를 검사하지 못하는 문제와 실제 이른 후보를 함께 처리해야 한다.

실제 10분 후보 전수 재시험:

- 같은 반복 파일의 대응 릴리스 84개에 ±1.5초 허용으로 비교했을 때 **84개 모두 후보가 대응**했다. 기존 결과는 80개였다. 이 값은 이른 후보·검토 대상도 포함하는 후보 대응률이며, 확정 슛 정확도나 다양한 원본 영상의 공식 발견률이 아니다.
- 후보 탐지와 집중 재탐지 합 **287.45초**, API·DB 호출 없음. 이전 473.72초는 최초 탐지와 DB 대기를 포함한 다른 구간이라 그대로 같은 조건의 개선율로 비교하지 않는다.
- 기존 짧은 영상 6개에서도 후보 11개의 시각·발 좌표가 유지됐다.

## 3. 림과 코트·화각

기존 골대 점은 백보드에 있어 실제 림 중심보다 위쪽이었다. 대표 14~23초 구간에서 초기점을 `(718.58, 243.83)`과 시각적으로 보정한 `(718.58, 313.0)`으로 비교했다. 양쪽 모두 동적 림 탐지값과 후보 시각 `16.370·20.454초`가 같았다. 이 구간에서는 자동 림 추적이 초기점 오차를 흡수했다. 초기점 오류가 모든 누락의 단독 원인이라고 볼 수 없다.

기존 코트 점을 다른 장면에 투영할 수 있는지 특징점으로 검증했다. 같은 구도의 네 표본은 보류한 대응점의 중간 오차 약 **0.84~0.99픽셀**로 일치했다. 반면 약 92·98·493초의 바뀐 화각은 검증을 통과하지 못했다. 바닥 특징점만으로 별도 시도해도 안정적인 모서리 대응을 확정하지 못했다.

실험본에서는 카메라별 코트 변환을 따로 받을 수 있게 했다. **검증하지 못한 새 화각에는 이전 숫자 좌표를 주지 않고 새 카메라 해석을 사용한다.** 자동으로 새 코트 모서리를 찾는 UI를 다시 추가한 것이 아니다.

실제 Terra 위치 시험은 92.568·98.252초를 기존 카메라·좌표와 새 카메라·이전 좌표 없음으로 비교했다. 새 시도에서는 두 장면 모두 신발과 3점선의 접촉이 모호해 위치 확인 필요로 남았다. 이는 정확한 구역이 확정됐다는 결과가 아니다. 경계 장면의 독립 정답과 새 화각의 수동 기준점 확인은 여전히 필요하다.

## 4. 병렬 외의 속도 개선과 결과

### 동일한 입력을 더 빨리 준비

기존 방식은 각 시각마다 영상을 다시 탐색했다. 새 방식은 필요한 첫 프레임으로 한 번 이동하고 순서대로 읽는다. 기본 판단·득점 확인 입력 9묶음의 **인코딩된 이미지와 라벨이 완전히 같았고**, 준비 합계는 **23.3686초 → 7.1000초**였다(약 69.6% 감소). 원본 끝에서 득점 장면이 부족한 마지막 입력도 양쪽에서 같은 오류가 났다. 이미지 수를 줄여 얻은 속도라는 뜻이 아니다.

### 2차 확인의 입력 중복 감소

전체 화면 8장과 림 크롭을 보내던 방식 대신 전체 화면은 앞뒤 2장, 림 주변은 100ms 간격으로 촘촘히 보냈다. 전체 맥락은 유지하면서 반복 전송을 줄였다.

| 같은 6건 합계 | 기존 득점 확인 | 새 촘촘한 림 확인 |
|---|---:|---:|
| 득점 정답 일치 | 6/6 | 6/6 |
| 입력 토큰 | 80,916 | 56,220 |
| 이미지 준비 | 14.0368초 | 3.8025초 |
| API 응답 대기 합 | 29.8577초 | 28.1374초 |

입력은 약 30.5%, 준비는 약 72.9% 감소했다. API 응답 감소는 약 5.8%로 작고 호출 시점의 서버 변동도 있으므로 고정 개선율로 보장하지 않는다. 테스트된 여섯 건 외에 이 입력이 항상 기존과 같은 정확도라고 주장하지 않는다.
