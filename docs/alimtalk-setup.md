# ShotLog 카카오 알림톡 설정 안내

후속 사용자 결정으로 현재 결과 알림은 Gmail로 전환했다. 현재 운영 설정과 시험 순서는 [Gmail 알림 안내](gmail-notification-setup.md)를 따른다. 아래 내용은 앞서 검토·구현한 카카오 알림톡의 당시 기록이다.

2026-11-05 카카오와 SOLAPI 공식 안내를 확인했다. 후속 사용자 요청으로 SOLAPI를 사용하는 서비스 연결 코드를 구현했다. 사용자는 채널·발송 서비스·템플릿 준비 전이라고 답했으므로 실제 발송은 미검증이다. 아래 발송 계정 설정 후 본인 휴대폰으로 최종 확인한다.

## 1. 카카오 채널 만들기

[카카오톡 채널 관리자센터](https://center-pf.kakao.com/)에서 사업용 카카오 계정으로 로그인하고 채널을 만든다. 채널명은 ShotLog, 검색용 ID와 카테고리·프로필을 설정한다. 이후 비즈니스 채널 심사를 신청하고 해당 유형에 맞는 사업자등록증·고유번호증 등 증빙을 준비한다. 카카오 안내에는 일부 개인 자격의 심사 경로도 있으므로 해당되는 증빙 요건을 확인한다. 채널 공개·검색을 켜고 고객센터 연락처를 입력한다. [카카오 채널 시작 안내](https://kakaobusiness.gitbook.io/main/channel/start), [알림톡 준비 안내](https://kakaobusiness.gitbook.io/main/ad/infotalk)

## 2. 발송 서비스에 채널 연결

[SOLAPI 콘솔](https://console.solapi.com/)에 가입한 뒤 메시지의 발송 준비 메뉴에서 카카오 채널/그룹을 연다. 채널 연동에서 채널 검색용 ID, 카테고리와 관리자 휴대폰 번호로 인증한다. 필요한 관리자 추가 인증도 설정한다. 제공사의 본인·사업자 확인 및 충전 조건은 실제 콘솔에서 확인한다. [SOLAPI 채널 연결 안내](https://solapi.com/guides/kakao-make-channel)

## 3. 분석 완료 템플릿 신청

메시지 → 발송 준비 카카오/네이버/RCS → 카카오 → 알림톡 템플릿에서 등록한다. 연결한 채널을 고르고 아래처럼 고정된 완료 안내와 필요한 변수, 결과 화면으로 가는 웹 링크 버튼을 넣는다. 각 변수의 예시 값도 함께 입력해 심사를 요청한다. 승인은 심사 결과를 확인해야 한다. [템플릿 등록 절차](https://solapi.com/guides/kakao-ata-guide), [카카오 심사 기준](https://kakaobusiness.gitbook.io/main/ad/infotalk/audit)

예시 본문은 다음과 같다.

```text
[ShotLog 분석 결과]
#{분석명}
전체 #{전체슛}개 · 성공 #{성공}개 · 실패 #{실패}개

AI 연습 요약
#{AI요약}

다음 연습
#{연습과제}

결과와 전체 리포트를 확인해 주세요.
```

버튼명은 ‘결과 및 AI 리포트 보기’로 설정한다. 모바일 링크에는 실제 배포 도메인의 결과 주소를 사용하고 분석 ID를 변수로 연결한다. 현재 localhost 주소는 휴대폰의 서비스 링크로 사용할 수 없으므로 배포 주소가 준비돼야 한다. 로그인 후 본인 기록에 접근하는 기존 권한 처리를 유지한다.

코드가 사용하는 변수명·고정 문구·버튼명을 위 내용과 일치시킨다. AI 요약·연습 과제 변수를 포함하는 템플릿의 승인 여부는 심사 결과를 확인해야 한다. 본문은 치환 후1,000자 이내로 제한한다. 요약은300자, 첫 연습 과제는200자까지 담고 전체 리포트는 버튼으로 연결한다. [SOLAPI 알림톡 규격](https://solapi.com/developers/api/messages-ata)

## 4. 발송 정보 준비

콘솔의 API 키 관리에서 API Key와 API Secret을 발급한다. 채널 ID와 승인된 템플릿 ID도 확인한다. 실제 값은 백엔드의 비밀 설정에만 보관한다. 채팅에 값을 전달할 필요는 없다. [SOLAPI 인증 설정](https://solapi.com/developers/api/authentication-api-key)

## 5. 본인 번호로 시험

충전·발송 준비 후 콘솔의 메시지 보내기에서 채널과 승인 템플릿을 선택한다. 본인 휴대폰 번호, 변수 예시, 실제 접근 가능한 결과 링크를 넣고 미리보기와 한 건 발송을 확인한다. 수신 문구·변수·버튼 이동·로그인 후 해당 결과 접근을 차례로 확인한다. SMS 대체 발송을 추가한다면 별도 발신번호 등록 요건도 확인한다. [콘솔 발송 안내](https://solapi.com/guides/kakao-ata-guide)

## 6. 백엔드 설정

backend/.env에 다음 항목을 설정한다. 실제 값은 이 문서나 채팅에 복사하지 않는다.

```dotenv
KAKAO_NOTIFICATIONS_ENABLED=false
SOLAPI_API_KEY=
SOLAPI_API_SECRET=
SOLAPI_KAKAO_PF_ID=
SOLAPI_KAKAO_TEMPLATE_ID=
PUBLIC_APP_URL=
```

SOLAPI 콘솔의 API 키·Secret, 연결한 카카오 채널 프로필 ID와 승인 템플릿 ID를 각각 입력한다. PUBLIC_APP_URL은 휴대폰에서 열 수 있는 서비스의 HTTPS 주소이며 경로·쿼리를 붙이지 않는다. 예를 들어 실제 서비스가 해당 주소에 배포되어 있다면 `https://shotlog.example.com` 형태다. Supabase의 Site URL·Redirect URLs와 웹 로그인 설정도 실제 배포 주소에서 동작하도록 맞춘다.

코드를 다른 설치에서 사용할 때는 backend에서 가상환경 Python으로 `python -m alembic upgrade head`를 실행해 알림 신청 테이블을 추가한다. 현재 개발 DB에는20261105_0009까지 적용됐다. 채널·템플릿·공개 주소 확인을 마친 뒤 KAKAO_NOTIFICATIONS_ENABLED=true로 바꾸고 백엔드를 재시작한다. 실제 값이 준비되지 않으면 화면에는 ‘카카오톡 알림을 준비하고 있습니다’가 표시된다.

## 7. 사용자 흐름과 발송 조건

1. 분석 진행 화면 또는 결과 화면의 ‘카카오톡 결과 알림’에서 알림 신청을 연다.
2. 본인 휴대폰 번호를 입력하고 분석 결과·AI 리포트 요약 수신과 필요한 리포트 생성에 동의한 뒤 신청한다.
3. 분석 후 위치나 결과 확인이 남으면 기존 결과 화면에서 확인·저장한다. 대기 중 신청은 취소할 수 있다.
4. 백엔드가 약15초 간격으로 대기 신청을 확인한다. 완료된 분석에 슛이 한 개 이상 있고 활성 분석 작업이 없으며 모든 공개 가능한 슛의 유효 위치와 성공/실패가 확정된 경우에 처리한다. 종류만 미확정인 경우에는 이 조건을 막지 않는다.
5. 최신 저장 리포트가 있으면 재사용한다. 없거나 통계가 바뀌었으면 기존 통계 전용 AI 요청으로 리포트를 생성한다. 영상은 리포트 요약 요청에 추가로 보내지 않는다.
6. 리포트 생성 후, 그리고 발송 직전에 다시 위치·결과·기록 지문을 확인한다. 중간 변경은 발송을 보류하고 재신청을 안내한다.
7. 카카오톡에 전체·성공·실패 수, AI 요약, 첫 연습 과제와 로그인 보호된 결과 링크를 보낸다. 문자 대체 발송은 꺼져 있다.

## 8. 중복·실패와 확인 범위

신청은 analysis_notifications에 저장하며 분석별 한 행과 원자적 처리권 획득으로 중복 요청·동시 작업을 제어한다. 서버 재시작 후 대기 신청을 다시 확인한다. 준비 중 프로세스가 종료되면 처리권 만료 후 재개한다. 발송 중 종료되거나 응답이 끊기면 ‘발송 여부 확인 필요’로 보존하며, SOLAPI 콘솔에서 해당 분석 ID의 발송 여부를 먼저 확인한다. 확실한 거절·리포트 실패는 오류 원인을 확인한 뒤 재신청할 수 있다.

SOLAPI의 정상 접수 응답은 화면에서 ‘발송 요청이 접수됐습니다’로 표시한다. 휴대폰 최종 수신까지 확인한 상태와 구분한다. [발송 응답 규격](https://solapi.com/developers/api/messages)

전화번호는 서버 DB에 보관하고 화면 조회에서는 끝 네 자리만 표시한다. 로그인 소유권 검사를 적용하고 새 테이블에는 RLS를 켰다. 신청 취소 시 수신 번호를 지운다. 분석 삭제 시 연결된 신청도 DB 외래키로 함께 제거된다.

2026-11-05 자동 시험에서 위치/결과 미정·범위 밖 좌표·활성 작업·실패/빈 분석 차단, 마지막 확인 후 한 번 발송, 최신 리포트 재사용, 동시 처리, 생성/발송 직전 변경, 중단 복구·타임아웃, 신청 취소·계정 격리·HMAC 인증·접수/거절 응답을 확인했다. 전체 백엔드681개·프런트51개와 빌드를 통과했다. 날짜 정규화·수동 리포트 생성 대기 보완 후 알림 관련23개를 다시 통과했다. 외부 AI·발송 서비스는 가짜 응답으로 시험했으며 실제 카카오 수신·승인 템플릿·공개 링크 이동은 설정 후 본인 번호로 확인해야 한다.
