# 8번 좌우 반전 원인과 수정

새10분 분석 `b0fd3395-7cef-4153-ad5b-74655bb5b846`의8번은02분30.933초다. 이전 분석과 같은 시각, 같은 코트 변환 행렬과 같은 발 추적 자료를 사용했지만 AI의 공통 카메라 해석이 달랐다.

| 자료 | 이전 | 새10분 분석 |

공통 해석 생성기는 기준점에서 구한 좌우 방향만 교체했다. 반대되는 카메라 이름과 앞뒤 축 설명은 원래 AI 응답을 유지했다. 상세 슛 요청은 이 충돌한 설명을 함께 받았고, 수치 좌표와 구역 이름이 서로 일치하므로 기존 좌표·구역 검사가 반전을 잡지 못했다. 사람 상자 하단이 실제 신발 접지점이 아니라는 기존 보호 조건 때문에 발 환산값도 제공되지 않은 장면이다.

원본에 검증된 페인트존 네 모서리를 표시해 오른쪽 선 바깥의 슈터를 확인했다. 같은03:20 전체 실행의 재사용 실패나 새 후보 탐지 차이로 설명할 근거는 없다.

## 코드 변경

- 검증된 코트 변환과 원본 크기로 좌우·앞뒤 축을 함께 계산한다.
- 베이스라인 좌우, 자유투선 좌우 네 모서리를 원본 전체 화면의 백분율 위치로 전달한다. 영상 크기 변화에도 기준이 유지된다.
- 이 두 축을 사용할 때는 이미지 단독으로 추정한 카메라의 사이드라인 이름을 상세 요청에서 제외한다. 원래 AI 추정은 진단 기록에 보존한다.
- 기준점으로 선수의 정확한 XY나 신뢰도를 대신 만들지 않는다. 기존 코트 검증·접지·득점·신뢰도 기준을 유지한다.
- 변환이 없거나 특이 행렬·유효하지 않은 크기·축 퇴화이면 보정 자료를 만들지 않는다. 낮은 공통 구도 신뢰도를 임의로 올리지 않는다.

## 저장과 남은 범위

사용자 요청에 따라8번의 새 AI 판정을 정상 자동 기록 저장 함수를 거쳐 반영했다. 현재 오른쪽 베이스라인 미드레인지 (40,7)이며 자동 판정 상태다. 성공 여부·종류·재생 구간·슛 ID를 유지했다. 다른29개 기록은 좌표·결과·종류·상태·수정 시각까지 같은 것을 저장 전후 비교했다.23번과1번은 검증 자료로만 사용했다.

작업 중인 분석이 없고8번이 아직 원래 자동 기록인지 확인한 뒤 반영했다. 현재 결과 파일에는8번의 수정 근거와 별도 검증 사용량을 남겼으며 원래 작업 사용량을 다시 합산하지 않았다. 이전 응답과 저장 전후 자료는 `backend/work/verification-2026-11-05/shot8-orientation`에 보관했다.

최종 백엔드 전체659개 시험이 통과했다. 기존 Starlette/httpx·SQLite 날짜 변환 경고 두 개가 남아 있다. 실제 Chrome 직접 조작은 이번 수정 확인에 포함하지 않았다. 웹 백엔드는 자동 재시작 없이 실행 중이며 앞선 재시작 명령이 자동 승인 검토에서 차단된 상태다. 새 AI 검증과 저장은 수정된 코드를 읽는 새 프로세스로 실행했다. 향후 웹 분석에서 이 수정판을 쓰려면 백엔드 재시작 반영이 필요하다.

후속으로 사용자가 백엔드·프런트 재시작을 새로 요청했다. 활성 분석0개 확인 후 최신 소스로 두 서버를 재시작했고 HTTP200·새 API 경로·기존30개와8번 수정 좌표 보존을 확인했다. 위 서버 반영 대기는 해소됐다. 상세 실행 기록은 plan.md와 test-plan.md의 같은 날짜 마지막 항목을 따른다.
