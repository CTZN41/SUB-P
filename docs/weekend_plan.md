# 주말 촬영·코트 인식 개선 계획

작성 기준: 2026-10-30 / 촬영 예정: 10월 31일(토)~11월 1일(일) / 발표 예정: 11월 6일(금)

## 1. 이번 작업의 목표

같은 반코트를 **① 사이드라인에서 옆으로 보는 구도**와 **② 사이드라인에서 비스듬히 보는 구도**로 촬영한다. 지금 가진 모델과 코트 보정 기능을 두 구도에 똑같이 적용해, 코트 선·골대·선수 발·슛 위치를 어느 쪽에서 더 안정적으로 찾는지 비교한다. 더 나은 구도를 고른 뒤 그 구도의 실제 영상으로 코트 인식을 보완하고, 학습에 사용하지 않은 새 장면에서 다시 검증한다.

이번 발표의 우선 대상은 **한 명이 연습하는 고정 카메라 영상**이다. 촬영 구도를 고르는 기준은 슛 발견 개수만이 아니라 **코트 전체의 위치 정확도**다. 한 구도에서 잘된 결과를 다른 코트나 조명에서도 보장한다고 말하지 않는다.

## 2. 지금 알고 있는 출발점

- 서비스는 React·TypeScript + FastAPI + Supabase PostgreSQL을 사용한다. 영상 분석은 로컬 YOLO와 OpenAI 보조 판정을 사용한다.
- 현재 코트 자동 제안은 페인트존 네 점과 골대 중심을 우선 찾고, 실패하면 학습된 코트 기준점 모델을 시간상 여러 프레임에 적용한다. 제안은 사용자가 확인한 뒤 저장한다.
- 코트 위치 확인 화면의 초기 네 점은 반코트 외곽 네 모서리로 시작하지만, 자동 제안이 성공하면 **페인트존 네 모서리와 그에 맞는 코트 좌표**로 바뀐다. 실제로 어느 네 점을 사용하는지 반드시 함께 기록해야 한다.
- 기존 학습 모델은 주로 페인트존 기준점과 골대를 배우도록 만들어졌다. **반코트 외곽 네 꼭짓점을 자동으로 잘 찾는 모델이라고 가정하면 안 된다.** 외곽 꼭짓점으로 바꾸려면 정답 표시 방식과 모델 출력, 화면·저장 흐름을 맞춰야 한다.
- 기존 다른 영상 22초 시험에서는 실제 슛 4개를 모두 찾았고, 2026-10-30 중복 후보 보완 뒤에는 후보도 4개가 남았다. 다만 슛 위치는 기존 측정에서 4개 중 2개만 정확했다. 이 수치는 새로 촬영할 영상의 예상 정확도가 아니라 비교를 위한 출발 기록이다.
- 코트 기준점 학습 모델은 특정 장면에서 개선됐으나 다른 사진에서는 오차가 커진 적이 있다. 여러 프레임에서 같은 위치를 안정적으로 가리키지 못하면 자동 확정하지 않는 현재 안전장치를 유지한다.

## 3. 주말에 사용자가 준비할 것

- 1.7m 삼각대, 스마트폰, 같은 농구공과 같은 반코트. 스마트폰 후면 기본 카메라 1배를 우선 사용한다.
- 두 구도 모두 **같은 해상도와 프레임률**로 찍는다. 가능하면 4K·60fps, 저장 공간이 부족하면 1080p·60fps로 통일한다. 촬영 중 줌·각도·삼각대 위치를 바꾸지 않는다.
- 영상에 베이스라인 양 끝, 양쪽 사이드라인, 하프코트 라인 양 끝, 3점선, 페인트존, 골대·네트가 가능한 한 보이게 한다. 네 외곽 꼭짓점이 나오도록 물러나되 공이 지나치게 작아지지 않게 한다. 외곽 꼭짓점 하나가 가려지면 그 사실을 적고 억지 정답점을 만들지 않는다.
- 두 구도에서 **같은 선수, 같은 슛 위치, 비슷한 시간대와 조명**으로 찍는다. 화면 바깥 사람이 포함되면 촬영과 분석에 필요한 동의를 확인한다.
- 원본 MP4를 편집·재인코딩하지 않고 보관한다. 파일명 예: `side_train.mp4`, `side_test.mp4`, `diagonal_train.mp4`, `diagonal_test.mp4`. 파일명은 구도를 구분하기 위한 예시다.
- 두 구도의 촬영 시작 시 **선수가 없는 코트 10~15초**를 찍는다. 그 뒤 사람이 화면 안에서 좌우, 베이스라인에서 하프코트 방향으로 이동하면서 주요 위치에서 1~2초씩 멈춘다.
- 왼쪽·정면·오른쪽 미드레인지, 양쪽 엘보, 양쪽 코너 3점, 정면 3점, 골밑 등 **같은 위치 순서로 각 구도에서 2~3회씩 슛**을 시도한다. ‘엘보’는 자유투선 양 끝, ‘45도’는 그 바깥 윙으로 구분해 기록한다. 시간이 부족하면 좌·정면·우와 가까운 거리·먼 거리의 조합부터 찍는다.
- 가능하면 각 구도에서 촬영 조건을 그대로 유지한 채 **별도의 두 번째 연습 영상**을 찍는다. 첫 영상은 학습 자료 후보, 두 번째 영상은 최종 시험용으로 남긴다. 시험용 영상의 어떤 프레임도 학습에 섞지 않는다.
- 간단한 정답표를 적는다: 파일명, 슛 시각(대략적인 초), 실제 구역, 성공/실패, 선수 발이 바닥에 닿은 위치를 눈으로 확인할 수 있는 프레임. 촬영 당시 사람이 기억하는 정보와 영상 재생으로 확인한 정보를 구분한다.

## 4. 촬영 구도 두 가지

| 항목 | A. 옆에서 보는 구도 | B. 비스듬히 보는 구도 |
| --- | --- | --- |
| 카메라 | 한쪽 사이드라인 바깥, 자유투선과 하프코트 사이쯤에서 코트 중앙을 향함 | 사이드라인 바깥에서 골대와 반코트 중앙을 대각선으로 함께 향함 |
| 높이 | 둘 다 같은 1.7m | 둘 다 같은 1.7m |
| 확인할 위험 | 먼 쪽 선과 선수 발이 가려지는지, 공이 작아지는지 | 코트 좌우·깊이를 헷갈리는지, 먼 쪽 코너가 잘리는지 |
| 공통 조건 | 골대·네트, 3점선, 네 외곽 꼭짓점, 선수 전신과 공이 영상 안에 보이는지 확인 | 동일 |

카메라를 너무 멀리 두어 공이 거의 보이지 않는다면 네 꼭짓점만을 위해 무리하게 더 넓히지 않는다. 어느 선이 잘렸는지 기록하고 보이는 여러 바닥 기준점으로 보정할 방법을 따로 검토한다.

## 5. 촬영 후 우리가 할 일: 기존 모델로 먼저 비교

1. MP4의 길이·해상도·프레임률, 흔들림·화면 잘림·역광을 확인한다. 각 구도의 빈 코트 장면과 실제 슛 장면을 모두 본다.
2. 두 구도에서 동일한 간격의 프레임을 뽑고, 사람이 반코트 네 외곽 꼭짓점(베이스라인×양쪽 사이드라인, 하프코트 라인×양쪽 사이드라인), 페인트존 네 모서리, 골대 중심을 **보이는 경우에만** 표시한다. 가린 점은 ‘보이지 않음’으로 기록한다.
3. 현재 색상·림 자동 제안과 기존 두 코트 기준점 모델을 **각각** 실행한다. 현재 모델은 페인트존 점을 출력하므로 외곽 네 꼭짓점의 검출률로 잘못 계산하지 않는다. 기준점 종류별 정답과 모델 출력을 맞춰 비교한다.
4. 동일한 촬영 자료에서 기존 선수·공·골대 탐지와 슛 후보 분석을 실행한다. 두 구도에 같은 분석 설정과 같은 정답표 작성 규칙을 적용한다.
5. 각 구도별로 다음을 표로 정리한다: 바닥 기준점이 충분히 보인 프레임 비율, 보이는 점의 위치 오차, 고정 카메라에서 점이 흔들린 정도, 골대·공·선수 탐지 상태, 실제 슛 발견 수와 잘못 추가한 수, 발 위치의 14개 구역 일치 수, `확인 필요` 수, 처리 시간.
6. 수동으로 정확하게 맞춘 네 외곽 꼭짓점의 코트 변환도 한 번 시험해 **촬영 구도 자체의 한계**와 **자동 모델의 한계**를 구분한다. 계산한 3점선·페인트존이 실제 선과 맞는지, 좌우가 뒤집히지 않았는지 확인한다.
7. 위 결과가 더 안정적인 구도를 고른다. 한쪽이 슛은 더 잘 찾고 다른 쪽이 코트 위치는 더 잘 찾는다면 각 지표를 함께 보여주고, 발표에서 중요한 14개 구역 정확도와 공 가시성을 우선하여 결정한다. 동률이면 촬영·재현이 쉬운 구도를 택한다.

## 6. 선택한 구도의 코트 인식 개선

1. **학습할 기준점을 먼저 확정한다.** 외곽 네 꼭짓점이 계속 보이면 이를 주 기준으로 삼고, 페인트존 모서리·자유투선 끝·골대 중심을 검사용 보조 기준으로 사용한다. 외곽이 가려지는 장면이 많으면 보이는 바닥 기준점을 네 개 이상 조합하는 방식으로 바꾼다. 골대는 바닥 평면의 네 점에 섞지 않는다.
2. 선택 구도의 학습용 영상에서 빈 코트, 선수 가림, 밝기 변화, 다른 슛 위치를 고르게 뽑는다. 같은 장면의 거의 동일한 프레임만 반복해서 학습하지 않는다. 실제 보이는 점에 사람이 정답을 표시하고 가려진 점은 가려짐으로 남긴다. 생성 이미지를 실제 촬영 정답처럼 사용하지 않는다.
3. 현재 5점(페인트존 네 점+골대) 모델과 새 외곽 기준점의 **점 이름과 순서가 다름**을 코드·데이터에서 명시한다. 점 종류를 늘리거나 바꿀 때는 출력 형식, 좌표 대응, 화면 표시와 저장값을 함께 갱신한다. 기존 모델의 이름만 바꿔 새 점을 검출했다고 처리하지 않는다.
4. 현재 학습된 모델을 비교 기준으로 남겨두고, 선택 구도 학습 자료로 모델을 추가 학습하거나 코트 선 검출 방식을 보완한다. 실제 촬영 조건에 맞춘 결과만 별도 모델로 저장한다. 원본 모델과 결과를 덮어쓰지 않는다.
5. 여러 연속 프레임의 예측이 같은 코트 위치에 모이는지 확인하고, 뒤집힌 네 점·서로 교차한 선·가린 점을 억지로 채운 결과를 거른다. 안정적인 경우에만 자동 **제안**하고 사용자가 확인할 수 있게 한다.
6. 선수 발 위치는 확정한 바닥 변환으로 14개 구역에 넣는다. OpenAI가 화면을 보고 추측한 구역과 다르면 근거를 비교하되, 잘못된 위치를 자동 확정하지 않는다.

## 7. 학습 뒤 최종 시험과 통과 기준

- 선택한 구도의 **별도 시험 영상**을 학습·모델 선택·임계값 조정에 사용하지 않고 마지막에 한 번 적용한다. 같은 영상의 인접 프레임을 학습과 시험에 나눠 넣어 정확도가 높아 보이게 하지 않는다.
- 사람이 표시한 보이는 기준점과 모델 예측의 거리, 네 점이 모두 안정적으로 나온 비율, 프레임 사이 흔들림, 코트 선이 실제 선에 겹치는 정도를 기록한다. 반대 구도의 시험 영상에도 적용해 성능이 얼마나 달라지는지 남긴다.
- 사람이 확인한 슛마다 실제 구역과 자동 구역을 대조한다. 특히 양쪽 코너·엘보·정면·골밑과 경계 부근에서 좌우 뒤집힘 및 거리 오판을 확인한다. 슛 누락과 중복 후보도 함께 센다.
- 임시 목표: **보이는 네 외곽 기준점을 안정적으로 찾고, 같은 고정 영상에서 점이 크게 흔들리지 않으며, 별도 시험 영상의 주요 슛 위치를 14개 구역에 대부분 정확히 배치**한다. 시험 샘플 수가 적으면 퍼센트만으로 합격을 선언하지 않고 `맞은 개수/실제 개수`와 실패 장면을 함께 제시한다. 이전의 4개 중 2개 위치 정확도와도 비교한다.
- 기준을 못 넘으면 학습을 계속 반복해 숫자를 맞추지 않는다. 원인을 점 가림·코트선 불명확·원근 변환·발 탐지·슛 후보 오류로 나눠 확인하고, 사용자 확인이 필요한 경우에는 코트 위치를 자동 확정하지 않는다.
- 모델 성능이 충분하면 그 구도를 발표 권장 촬영법으로 문서화한다. 그렇지 않으면 가장 정확한 수동 기준점 확인 절차와 제한 사항을 발표 자료에 포함한다. 한 구도에서의 성공을 모든 구도에 대한 성공으로 표현하지 않는다.

## 8. 파일·진행 기록

- 이 문서는 촬영과 후속 비교·학습을 위한 계획이다. **현재 모델의 새 구도 성능이나 추가 학습 성공은 아직 측정하지 않았다.**
