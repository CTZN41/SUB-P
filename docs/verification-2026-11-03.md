5. 같은 화면 근거를 쓰더라도 현재 AI는 후보마다 독립 요청으로 숫자 좌표를 추정한다. 좌표를 재사용하거나 같은 위치로 고정하는 장치는 없다. 같은 환산값 `(10.8888,23.0294)`인55/69번도 재검토 신뢰도48%/57%로 달랐다. 이것만으로 두 요청의 모든 이미지·문구가 완전히 같았다고 단정하지는 않는다.

다음 과제는 릴리스와 실제 접지 구간의 일관성, 영상 단독 거리 판단과 숫자 위치의 서로 다른 신뢰도를 구분하는 방법, 고정 구도의 안정된 바닥 근거 재사용이다. 반복본만 좌표를 같게 덮어써 실제 정확도를 높인 것처럼 보이게 만들지 않는다. 별도 실촬영/독립 영상의 정답표가 있어야 일반 위치 정확도를 측정할 수 있다.

### 적용 상태·디자인 작업

- 서비스 코드·시험과 결과 문서를 저장했다. 자동 승인 검토가 백엔드 종료·재시작 명령을 정책상 차단해 재시작하지 못했다. 기존 서버는 HTTP 정상 응답하며 이전 코드로 계속 실행 중이다. 새 코드의 웹 전체 분석은 미검증이고 서버 재시작 후 별도 시험이 필요하다.
- 프론트 코드는 수정하지 않았다. 기능·구조를 유지하는 디자인 초안을 `SDD.md`의22절에 정리했다. 정확도 안정화가 끝났다는 전제는 아니며 실제 화면 변경은 아직 하지 않았다.


### 2026-11-03 로컬 디자인 적용·영상별 선택 삭제·가독성

- 회색·라임 공통 테마를 적용하고 홈 장식 코트·3D 번호 안내를 제거했다. 최근 기록은 사용자의 최종 요청대로 추가 이동하지 않았다.
- 영상별 개별/전체 선택·선택 해제·확인창·선택 삭제를 구현했다. 성공한 기록은 제거하고 실패한 기록만 보존·재시도한다. 서버의 기존 단건 삭제 규칙을 재사용한다.
- 등록/코트/선수/진행/결과/영상별/월별 화면의 공통 줄바꿈·폭·버튼 행을 정리했다. 긴 동의·미지정 기준점·삭제 경고는 의미별로 나눴다.
- 프론트16개 자동시험·빌드 통과, 린트 오류0(기존 경고4). Chrome 실제 프론트와 모의 기록 시험 화면에서 선택·취소·전체 선택·부분 실패와 긴 파일명을 확인했다. 새 유료 분석이나 실제 DELETE는 보내지 않았다.
- 실제 API 목록이 검증 후반0개여서 데이터가 필요한 모든 화면의 최종 상태를 실제 기록으로 재검증하지는 못했다. 자세한 검증·미확인·다음은 docs/ui-design-verification-2026-11-03.md.
- 다음: 새 실제 분석을 사용자가 등록한 뒤 코트/진행/선수/결과 편집의 긴 문구를 화면으로 최종 확인. 실제 일괄 삭제는 삭제해도 되는 시험 기록으로 검증한다.
