# ShotLog 기능 동작 설명서(SPEC)

> 2026-11-04 최신 위치 정책은 일반 좌표 신뢰도65% 이상을 저장합니다. 좌표 신뢰도가 별도로 있으면 두 점수의 최솟값을 사용하며 좌표 범위·구역 일치를 확인합니다. 접지 측정과 독립3점선 증거는 별도70% 기준입니다. 기존 AI 점수와 좌표를 재작성하지 않고 저장 판정만 새 기준으로 계산합니다. 최근10분 기록은30개 중27개 위치를 저장해 위치 확정률90%를 확인했습니다. 상세한 재적용 범위는 [검증 기록](analysis-reuse-verification-2026-11-04.md)을 따릅니다.

> 2026-11-03 추가 요구: 이메일 로그인·회원가입과 Google·카카오·네이버 간편 로그인 연결을 추가했습니다. 초기 회원가입 제외 범위는 확장됐습니다. Google 설정과 로컬 로그인 보호를 켜고 백엔드를 재시작했으며, Chrome에서 로그인된 홈과 새로고침 후 유지를 확인했습니다. 이메일 가입·네이버·카카오·두 계정 접근 분리는 아직 미검증입니다. 상세: [로그인 설정 안내](auth-setup.md).

## 1. 문서 목적

> 2026-11-04 위치 후속: 3D 마커 중심은 저장 좌표를 유지합니다. 후보 시각이 보정되면 발 궤적을 다시 확보하고 안정된 시각의 보조 환산값과 실제 신발 이미지를 구분합니다. 좌표 없는 응답도 영상 근거로 추가 검토하며 70% 자동 확정 기준은 유지합니다. 단계별 고정 구간과 기준 시각·경계 예외·시험 한계는 [복구 보고서](position-recovery-2026-11-04.md)를 따릅니다.

> 2026-11-04 최신 동작: 서비스 닉네임은 사용자 메타데이터 대신 `user_profiles` 고유 키로 확정합니다. 정규화·대소문자·연속 공백 차이를 제거해 중복을 막으며, 기존 중복은 가입 순서로 이전했습니다. 이메일 없는 계정의 이메일 추가는 본인 Supabase 인증 흐름을 사용하며, 다른 계정의 등록/인증 대기 주소를 거절하고 인증 전에는 완료로 표시하지 않습니다.

> 2026-11-04 추가 동작: 로그인한 사용자 자신의 프로필만 조회합니다. 이메일 가입의 닉네임은 필수이며 간편로그인 뒤 미등록 닉네임은 처음에 설정합니다. 인증된 이메일이 있는 간편로그인 계정의 미등록 비밀번호만 현재 사용자 권한으로 등록합니다. 이미 등록됐으면 조회 상태만 보여주고 변경 기능은 제공하지 않습니다. 닉네임은 표시용으로만 사용하며 접근 권한은 검증된 사용자 ID로 제한합니다.

> 2026-11-04 후속: 로그인 상태 유지 선택은 이메일·간편로그인 모두에 적용하며 기본은 미선택입니다. 세션 저장소·서버 쿠키의 지속 여부를 함께 전환하고 비밀번호는 저장하지 않습니다. 닉네임 재설정 여부와 계정 표시는 로그인 세션 메타데이터 대신 서버에서 확인한 본인 프로필을 사용합니다. 상세·브라우저 복원 한계·시험 범위는 `auth-setup.md` 후속 기록을 따릅니다.

이 문서는 `mvp.md`와 `PRD.md`, 그리고 2026년 10월 28일에 확정한 답변을 바탕으로 ShotMap AI의 기능이 실제로 어떻게 움직여야 하는지 설명합니다.

각 기능마다 다음 내용을 구분합니다.

1. 사용자가 무엇을 입력하거나 누르는지
2. 정상 처리되면 무엇이 저장되고 화면에 무엇이 보이는지
3. 잘못 입력하거나 처리에 실패하면 어떻게 되는지
4. 누가 보고 수정하거나 삭제할 수 있는지
5. 나중에 제대로 만들었는지 어떻게 확인할지

첫 버전은 현재 PC에서 한 명이 사용하는 로컬 프로그램입니다. 회원가입, 로그인과 인터넷 배포는 포함하지 않습니다.

## 3. 공통 용어

### 분석

영상에서 슛 후보를 찾고, 선수·위치·성공 여부·슛 종류를 판단하는 전체 작업입니다.

### 슛 후보

프로그램이 슛일 가능성이 있다고 찾은 영상 구간입니다. 사용자가 확인하기 전에는 틀릴 수 있습니다.

### 전체 슛 시퀀스

선수가 슛을 준비하기 시작한 순간부터 공의 성공 또는 실패가 확인되는 순간까지의 영상 구간입니다.

예시는 다음과 같습니다.

- 캐치 앤 슛: 패스를 받기 직전부터 결과가 확인될 때까지
- 드리블 풀업: 슛으로 이어진 드리블 동작부터 결과가 확인될 때까지
- 레이업: 골대로 진입하는 동작부터 결과가 확인될 때까지
- 제자리 슛: 슛 준비 자세부터 결과가 확인될 때까지

### 확인 필요

AI가 결과를 확실하게 판단하지 못하여 사용자가 영상을 보고 확정해야 하는 상태입니다.

### 코트 좌표

영상 속 슛 위치를 가상의 반코트 위 위치로 바꾼 값입니다. 3D 맵과 히트맵을 만드는 데 사용합니다.

## 4. 공통 상태

### 4.1 분석 상태

분석 한 건은 다음 상태 중 하나를 가집니다.

| 상태 | 뜻 | 화면에서 가능한 행동 |
|---|---|---|
| 등록 중 | 파일과 기본 정보를 확인하는 중 | 입력 수정, 등록 취소 |
| 설정 필요 | 코트 또는 선수 설정이 끝나지 않음 | 설정 계속하기, 삭제 |
| 대기 중 | 분석 시작 요청을 받음 | 기다리기, 취소 |
| 분석 중 | 영상을 실제로 처리하는 중 | 진행 확인, 취소 |
| 검토 필요 | 분석은 끝났지만 확인할 기록이 있음 | 슛 검토와 수정 |
| 완료 | 결과를 볼 수 있음 | 결과 보기, 수정, 삭제 |
| 실패 | 분석을 끝내지 못함 | 이유 확인, 다시 시도, 삭제 |
| 취소됨 | 사용자가 분석을 중단함 | 다시 분석, 삭제 |

### 4.2 슛 기록 상태

- `자동 분석`: AI가 만들었고 아직 사용자가 수정하지 않은 기록
- `확인 필요`: AI 판단이 불확실한 기록
- `사용자 확인`: 사용자가 내용을 확인하거나 수정한 기록

### 4.3 저장 원칙

- 등록한 원본 영상은 사용자가 삭제하기 전까지 현재 PC에 남습니다.
- 분석 결과와 사용자 수정 내용은 프로그램을 껐다 켜도 남습니다.
- 취소한 분석의 원본 영상은 남기고, 완성되지 않은 중간 결과는 제거합니다.
- 영상 삭제 시 연결된 선수, 슛 기록, 통계와 분석 결과를 함께 삭제합니다.
- 삭제한 내용은 첫 버전에서 복구하지 않습니다.

## 5. 화면 이동 구조

```text
시작 화면
├─ 새 영상 분석
│  ├─ 영상 등록
│  ├─ 코트 위치 확인
│  ├─ 선수 설정(다인원일 때)
│  └─ 분석 진행
├─ 최근 분석 기록
│  └─ 분석 결과
│     ├─ 3D 슈팅 맵
│     ├─ 2D 히트맵
│     ├─ 슛 기록 목록
│     └─ 슛 장면 및 수정
└─ 삭제 확인
```

진행 중인 분석 화면을 벗어나도 분석은 계속됩니다. 사용자는 최근 분석 기록에서 상태를 다시 확인할 수 있습니다.

## 6. 기능별 동작

### 6.1 시작 화면과 최근 기록

#### 사용자의 행동

- `새 영상 분석` 버튼을 누릅니다.
- 최근 분석 항목을 누릅니다.
- 분석 중인 항목을 눌러 진행 화면으로 돌아갑니다.

#### 정상 결과

- `새 영상 분석`을 누르면 영상 등록 화면으로 이동합니다.
- 최근 기록은 등록 날짜가 새로운 순서대로 보여줍니다.
- 각 항목에는 분석 이름, 촬영 형태, 등록 날짜, 영상 길이, 상태, 전체 슛 수와 성공률을 보여줍니다.
- 아직 결과가 없는 상태에서는 슛 수와 성공률 대신 현재 상태를 보여줍니다.

#### 실패 또는 빈 화면

- 저장된 기록이 없으면 `아직 분석한 영상이 없습니다`와 새 분석 버튼을 보여줍니다.
- 저장 정보를 읽지 못하면 기록이 없는 것처럼 가장하지 않고 불러오기 실패를 알립니다.

#### 접근 권한

- 현재 PC의 한 명의 로컬 사용자만 봅니다.
- 계정별 구분은 하지 않습니다.

#### 확인 방법

- 기록 세 개를 등록한 뒤 가장 최근 기록이 위에 있는지 확인합니다.
- 프로그램을 종료하고 다시 실행해도 목록이 남는지 확인합니다.
- 검색창과 필터가 표시되지 않는지 확인합니다.

### 6.2 영상 등록

#### 입력 항목

- 분석 이름: 필수
- 영상 파일: 필수
- 촬영 형태: 개인 연습, 1대1, 2대2, 3대3 중 하나
- 촬영 날짜: 선택
- 첫 선수 이름: 1대1·2대2·3대3에서만 선택 입력. 개인 연습에서는 입력칸을 표시하지 않고 `선수 A`로 시작
- 다른 사람 포함 여부: 필수 선택
- 다른 사람 포함 시 촬영·분석 동의 확인: 필수
- OpenAI 안내 확인 체크박스: 2026-11-04 사용자 요청으로 제거. 별도 확인은 필수가 아님

분석 이름은 앞뒤 공백을 제거한 뒤 1~100자여야 합니다. 공백만 입력할 수 없습니다.

#### 파일 조건

- 확장자와 실제 파일 형식이 MP4여야 합니다.
- 영상 길이는 40분 이하여야 합니다.
- 파일 크기는 5GB 이하여야 합니다.
- 한 번에 한 파일만 선택합니다.

#### 정상 처리

1. 사용자가 파일을 선택합니다.
2. 프로그램이 파일 이름, 크기, 길이, 해상도와 초당 프레임 수를 읽습니다.
3. 화면에 읽은 정보를 보여줍니다.
4. 사용자가 나머지 항목을 입력하고 다음 단계로 이동합니다.
5. 영상 정보와 원본 파일을 현재 PC에 저장합니다.
6. 분석 상태를 `설정 필요`로 저장합니다.

#### 화면 안내

- 1080p 미만이면 정확도가 낮아질 수 있다고 경고합니다.
- 60fps 미만이면 원본 프레임 수로 재생된다고 안내합니다.
- 반코트, 골대와 선수 전신이 보여야 한다는 촬영 조건을 보여줍니다.
- 경고가 있어도 파일 조건을 만족하면 사용자가 계속 진행할 수 있습니다.

#### 실패 처리

- MP4가 아니면 `MP4 영상만 사용할 수 있습니다`라고 표시합니다.
- 40분을 넘으면 실제 길이와 설정된 최대 40분 조건을 보여줍니다.
- 5GB를 넘으면 실제 크기와 최대 5GB 조건을 보여줍니다.
- 파일이 손상되었거나 읽을 수 없으면 다른 파일을 선택하도록 안내합니다.
- 필수 항목이나 확인이 빠지면 해당 항목 가까이에 이유를 표시하고 다음 단계로 넘어가지 않습니다.
- 저장 공간이 부족하면 필요한 공간을 확보한 뒤 다시 시도하도록 안내합니다.

#### 수정과 삭제

- 분석 시작 전에는 입력한 정보와 파일을 바꿀 수 있습니다.
- 분석 시작 후 원본 파일 교체는 지원하지 않습니다. 다른 파일을 분석하려면 새 분석을 만듭니다.

#### 확인 방법

- 정상 MP4, MP4가 아닌 파일, 40분 초과, 5GB 초과, 손상된 파일을 각각 시험합니다.
- 다른 사람이 포함된 상태에서 동의 확인을 하지 않으면 진행되지 않는지 확인합니다.
- 별도 OpenAI 확인 없이 등록·분석 준비로 진행할 수 있는지 확인합니다.

### 6.3 영상 기본 검사

#### 프로그램이 확인하는 내용

- 골대와 림을 찾을 수 있는지
- 반코트 주요 부분이 화면에 들어오는지
- 카메라 움직임이 심하지 않은지
- 선수의 발과 전신이 보이는지
- 영상이 지나치게 어둡거나 흐리지 않은지

#### 정상 결과

- 큰 문제가 없으면 `촬영 조건 확인 완료`를 보여주고 코트 설정으로 이동합니다.
- 문제가 있지만 분석을 시도할 수 있으면 경고 목록과 `계속 진행` 버튼을 보여줍니다.

#### 분석하기 어려운 경우

- 골대가 전혀 보이지 않거나 영상을 열 수 없으면 분석을 시작하지 않습니다.
- 반코트가 많이 잘리거나 카메라 움직임이 심하면 분석 정확도를 보장할 수 없다고 분명히 표시합니다.
- 사용자가 경고를 무시하고 진행한 사실을 해당 분석 기록에 남깁니다.

#### 확인 방법

- 권장 조건 영상과 골대가 없는 영상을 비교합니다.
- 경고 영상에서 사용자가 계속할지 중단할지 선택할 수 있는지 확인합니다.

### 6.4 코트 위치 확인

#### 화면 구성

- 영상의 대표 장면을 크게 보여줍니다.
- 사용자가 직접 옮길 안내용 바닥 기준점과 골대 위치를 영상 위에 겹쳐 보여줍니다.
- 바닥 기준점과 골대 기준점을 서로 다른 모양으로 표시합니다.
- 페인트존 네 모서리·반코트 네 모서리 선택과 확인 버튼을 제공합니다.

#### 기준점

- 코트 바닥 위에서 서로 떨어진 기준점을 최소 4개 사용합니다.
- 현재 코트 설정 화면의 기본값은 페인트존 네 모서리입니다. 1·2는 베이스라인 좌·우, 3·4는 자유투선 우·좌이며 가상 코트의 `(17,0)`, `(33,0)`, `(33,19)`, `(17,19)`에 각각 연결합니다. 반코트 전체 네 모서리가 모두 보이면 기존의 `(0,0)`, `(50,0)`, `(50,47)`, `(0,47)` 방식도 선택할 수 있습니다. 두 방식 모두 14개 구역 및 3D 코트와 같은 가상 좌표계를 사용합니다.
- 페인트존 기준을 선택했을 때 1·2는 골대 아래 끝선과 페인트존 좌·우 선의 교차점, 3·4는 자유투선과 페인트존 우·좌 선의 교차점에 직접 맞춥니다. 기존 기록에서 점 이름이 불분명하면 먼저 `페인트존 네 모서리`를 선택합니다.
- 골대 중심 위치를 별도로 확인합니다.
- 선택한 기준의 네 모서리가 보이지 않는 장면에서는 점을 추측해 저장하지 않고 다른 대표 장면이나 다른 기준을 선택합니다. 네 점을 서로 다른 기준의 선에 섞어 놓지 않습니다.
- 자동 코트 선 찾기는 제공하지 않습니다. 안내용 점은 실제 위치로 취급하지 않으며 사용자가 바닥 네 점과 림을 각각 직접 지정해야 저장할 수 있습니다.
- 기존 기록의 가상 좌표가 현재 선택한 기준과 다르면 화면 점을 그대로 옮겨 맞는 것처럼 표시하지 않습니다. 새 기준을 고른 뒤 바닥 네 점과 림을 다시 지정해야 확인란과 저장 버튼을 사용할 수 있습니다.

#### 사용자의 행동

- 기준이 되는 네 모서리가 모두 보이는 대표 장면을 고릅니다.
- 안내용 점을 마우스로 끌어 실제 코트 선 교차점과 림 중심에 놓습니다.
- 페인트존 네 모서리와 반코트 네 모서리 중 영상에 보이는 기준을 선택할 수 있습니다.
- 다섯 점을 지정한 뒤 확인란을 선택하고 저장합니다.

#### 정상 결과

- 확인된 기준점과 가상 코트 좌표의 관계를 저장합니다.
- 이후 모든 슛 위치를 같은 코트 기준으로 변환합니다.
- 개인 연습이면 분석 시작 전 확인 화면으로 이동합니다.
- 다인원 영상이면 선수 설정으로 이동합니다.

#### 실패 처리

- 기준점이 4개보다 적으면 확인할 수 없습니다.
- 기준점이 한쪽에 지나치게 몰리거나 순서가 뒤바뀌면 위치를 다시 확인하도록 안내합니다.
- 골대 위치를 정하지 못하면 분석을 시작할 수 없습니다.
- 선택한 기준의 네 모서리가 보이지 않으면 다른 대표 장면이나 다른 기준을 선택합니다. 보이지 않는 점을 추측해 저장하지 않습니다.

#### 확인 방법

- 안내용 점을 그대로 둔 상태에서는 저장할 수 없는지, 네 점과 림을 직접 맞춘 뒤에는 저장할 수 있는지 시험합니다.
- 기준점이 부족하거나 잘못 교차한 상태에서 확인이 막히는지 확인합니다.
- 같은 위치의 슛이 3D 코트에서도 같은 구역에 표시되는지 확인합니다.

### 6.5 선수 설정

#### 개인 연습

- 영상 등록 때 이름 입력칸은 표시하지 않고 `선수 A`로 시작합니다.
- 이름은 이후 선수 설정 화면에서 바꿀 수 있습니다.
- 영상에서 별도로 선수를 지정하지 않아도 한 명의 선수로 처리합니다.

#### 1대1·2대2·3대3

- 최대 6명의 선수를 등록합니다.
- 각 선수의 이름과 등번호는 선택 사항입니다.
- 영상 등록에서 첫 선수 이름을 입력했다면 선수 설정에 그 이름으로 한 명이 먼저 표시됩니다.
- 이름과 등번호를 모두 모르면 등록 순서대로 `선수 A`부터 `선수 F`까지 사용합니다.
- 같은 이름이나 같은 등번호가 있어도 등록은 가능하지만, 화면에서 구분하기 어렵다는 경고를 보여줍니다.

#### 영상에서 선수 지정

1. 프로그램이 선수들이 잘 보이는 대표 장면을 보여줍니다.
2. 사용자가 화면 속 한 선수를 누릅니다.
3. 등록한 이름·등번호 또는 임시 이름을 선택합니다.
4. 선택한 사람의 주변에 이름표와 테두리를 표시합니다.
5. 모든 선수를 지정한 뒤 확인합니다.

#### 정상 결과

- 선수 정보와 영상 속 첫 위치를 저장합니다.
- 분석 중에는 지정한 선수를 이어서 추적합니다.
- 추적이 끊기거나 서로 가려져 확실하지 않으면 해당 슛을 `확인 필요`로 보냅니다.

#### 실패 처리

- 촬영 형태에 필요한 인원보다 많이 등록할 수 없습니다.
- 같은 화면 위치에 두 선수를 겹쳐 지정할 수 없습니다.
- 선수가 보이지 않으면 다른 대표 장면으로 이동해 지정할 수 있습니다.
- 끝까지 지정하지 못한 선수가 있어도 분석은 진행할 수 있지만, 선수 구분 정확도가 낮아질 수 있다고 안내합니다.

#### 확인 방법

- 이름과 등번호가 있는 경우와 없는 경우를 각각 시험합니다.
- 정보가 없을 때 `선수 A~F`가 중복 없이 만들어지는지 확인합니다.
- 화면에서 누른 선수와 저장한 선수 이름이 연결되는지 확인합니다.
- 최대 6명보다 많이 등록할 수 없는지 확인합니다.

### 6.6 분석 시작

#### 사용자의 행동

- 파일, 동의, 코트와 선수 설정을 최종 확인합니다.
- `분석 시작` 버튼을 누릅니다.

#### 정상 결과

- 버튼을 누르기 전에는 분석하지 않습니다.
- 한 번 누르면 같은 분석을 중복 실행하지 않도록 버튼을 잠시 비활성화합니다.
- 상태를 `대기 중`으로 저장한 뒤 분석 화면으로 이동합니다.
- 실제 처리가 시작되면 상태를 `분석 중`으로 바꿉니다.

#### 시작할 수 없는 경우

- 원본 파일이 사라졌거나 읽을 수 없으면 시작하지 않습니다.
- 필수 동의, 코트 확인 또는 필요한 선수 설정이 빠지면 빠진 내용을 알려줍니다.
- OpenAI API 설정이 없으면 어떤 분석을 진행할 수 없는지 설명하고 완료를 가장하지 않습니다.

#### 확인 방법

- 버튼을 누르기 전 분석이 시작되지 않는지 확인합니다.
- 버튼을 빠르게 여러 번 눌러도 분석 작업이 하나만 생기는지 확인합니다.

### 6.7 분석 진행과 취소

#### 진행 단계

화면에는 다음 단계 중 현재 단계를 표시합니다.

1. 영상 준비
2. 코트와 골대 확인
3. 선수·공 추적
4. 슛 후보 찾기
5. 성공·실패와 슛 종류 판단
6. 결과 계산
7. 완료

정확한 남은 시간을 알 수 없으면 거짓 시간을 표시하지 않고 현재 단계와 처리한 영상 구간을 보여줍니다.

#### 취소

- `분석 취소` 버튼을 누르면 확인 메시지를 보여줍니다.
- 사용자가 다시 확인하면 가능한 안전한 지점에서 처리를 멈춥니다.
- 상태를 `취소됨`으로 저장합니다.
- 원본 영상, 등록 정보, 코트와 선수 설정은 유지합니다.
- 완성되지 않은 슛 후보와 중간 통계는 삭제합니다.
- `다시 분석` 버튼을 누르면 기존 설정을 확인한 후 처음부터 분석합니다.

#### 실패 처리

- 프로그램이 갑자기 종료되어도 다음 실행에서 해당 작업을 `분석 중`으로 계속 보여주지 않습니다.
- 복구할 수 없으면 `중단됨` 안내와 다시 분석 버튼을 제공합니다.

#### 확인 방법

- 각 단계 이름이 순서대로 표시되는지 확인합니다.
- 분석 중 화면을 이동했다 돌아와도 상태가 유지되는지 확인합니다.
- 취소 후 원본은 남고 중간 슛 기록은 남지 않는지 확인합니다.
- 취소한 영상을 다시 분석할 수 있는지 확인합니다.

### 6.8 AI 슛 분석

#### 프로그램의 역할

- 영상 프레임을 읽습니다.
- 선수, 공과 골대를 찾고 시간에 따라 추적합니다.
- 골대는 처음 지정한 한 좌표로 고정하지 않습니다. 각 프레임의 림 탐지를 따라가고, 잠깐 놓치면 최근 정상 위치를 최대 1.5초 동안 사용합니다.
- 골대 위치가 크게 바뀌면 새 장면으로 구분합니다.
- 슛일 가능성이 있는 구간을 찾습니다.
- 슛 순간의 선수 발 위치를 코트 좌표로 바꿉니다.
- 공의 이동과 림 주변 장면으로 성공 또는 실패를 판단합니다.
- 카메라가 이동해 기존 코트 보정과 맞지 않는 장면에서는 잘못된 위치를 저장하지 않고 `코트 위치 확인 필요`로 남깁니다.

#### 반코트가 일부만 보이는 영상

- 반코트 전체 네 모서리가 보이지 않아도 페인트존 네 모서리가 보이면 현재 화면에서 코트 위치를 맞출 수 있습니다. 반대로 반코트 네 모서리가 모두 보이면 그 기준을 선택할 수 있습니다.
- 선택한 네 모서리가 보이지 않으면 다른 선을 임의로 같은 좌표에 연결하지 않습니다. 현재 화면에서 제공하지 않는 기준점 조합은 별도 좌표 지정 방식이 준비된 뒤 적용합니다.
- 기준점이 4개보다 적거나 한쪽에 몰려 있으면 슛 시점·선수·결과는 분석하되 코트 좌표와 14개 구역은 자동 확정하지 않습니다.
- 장면 전환 뒤에는 이전 장면의 코트 변환값을 그대로 사용하지 않습니다.

#### OpenAI의 역할

- 전체 영상이 아니라 슛 후보의 필요한 장면만 확인합니다.
- 슛 시도 여부는 로컬 YOLO·선수 자세·공 궤적 분석으로 먼저 확정합니다. OpenAI는 이 후보를 다시 삭제하지 않고 슛 종류, 성공·실패와 슛 위치를 판단합니다.
- 슛 위치는 저장된 네 점 원근변환만으로 자동 확정하지 않습니다. 환산한 발 좌표를 보조 근거로 AI에 전달하고, 실제 신발·골대·페인트존·3점선과 함께 14개 구역을 판단합니다.
- 좌표와 구역 이름이 충돌하거나 환산 발 위치와 좌우가 명백히 다르면 Terra가 위치만 다시 검토합니다. 그래도 불일치하면 `위치 확인 필요`로 남깁니다.
- 위치 신뢰도가 70% 미만이면 좌표를 자동 저장하지 않습니다. 다른 모델이 위치를 덮어쓰지 않습니다.
- 위치 판정은 같은 고정 장면의 대표 프레임 여러 장으로 `카메라 방향 해석`을 한 번만 수행합니다. 이 공통 방향을 장면의 모든 슛에 재사용한 뒤 각 슛마다 `실제 신발을 탑뷰에 투영 → 거리와 14구역 판정`을 수행하고 결과를 남깁니다.
- 공통 카메라 방향과 개별 슛 위치는 Terra만 판단합니다. Terra가 방향을 확정하지 못하거나 위치 신뢰도가 75% 미만이면 다른 모델로 덮어쓰지 않고 `위치 확인 필요`로 남깁니다. Sol은 기존처럼 성공·실패 등 위치가 아닌 항목의 보조 검토에만 사용할 수 있습니다.
- 개별 슛 응답이 공통 카메라 방향과 다른 방향을 반환하더라도 공통 방향을 바꾸지 않습니다. 안전 검사에서 같은 장면의 방향 충돌이 남으면 해당 장면의 모든 자동 위치를 취소합니다.
- 기본 검토는 후보 시점 2.5초 전부터 3.5초 후까지의 전체 장면 12장과 릴리스 주변 선수 확대 장면 최대 4장을 사용합니다.
- 성공·실패가 불확실하면 골대에 공이 접근한 시점 주변을 촘촘하게 뽑은 골대 확대 장면과 전체 장면으로 득점만 따로 확인합니다.
- 득점 전용 Terra 검토로도 불확실할 때만 Sol이 득점 여부를 한 번 더 확인합니다.
- 슛 종류가 불확실하면 득점 결과와 별개로 `확인 필요`를 유지합니다.
- 림 통과가 직접 보이지 않으면 화면에 실제로 보이는 공의 낙하 방향, 선수의 리바운드 행동과 점수 표시 변화를 보조 근거로 사용할 수 있습니다.
- 프로그램이 정한 형식으로 결과를 돌려줍니다.

#### 저장할 슛 종류

한 슛에는 다음 중 대표 종류 하나를 저장합니다.

- 캐치 앤 슛
- 제자리 슛
- 드리블 풀업
- 사이드 스텝
- 레이업
- 덩크
- 페이더웨이
- 스텝백
- 턴어라운드
- 훅슛
- 기타
- 확인 필요

레이업과 덩크는 서로 다른 종류로 저장합니다. 골대 가까이에서 한 손으로 공을 위로 올려 놓으면 레이업이고, 공을 쥔 채 림 높이에서 아래로 밀어 넣으면 덩크입니다. 가까운 위치에서 뛰었다는 이유만으로 덩크라고 확정하지 않습니다.

스텝백, 턴어라운드와 훅슛의 정확도가 부족하면 억지로 확정하지 않고 `기타` 또는 `확인 필요`로 저장합니다.

#### 전체 슛 시퀀스 선택

- AI는 슛 준비가 시작된 시점과 성공·실패가 확인된 시점을 함께 저장합니다.
- 구간은 보통 3~15초를 목표로 합니다.
- 확실히 찾지 못하면 슛 후보 시점 5초 전부터 3초 후까지 사용합니다.
- 자동 구간이 20초보다 길면 우선 최대 20초를 보여주고, 원본 영상으로 이어서 볼 수 있게 합니다.
- 영상 처음이나 끝을 넘어가는 시간은 실제 영상 범위에 맞게 줄입니다.

#### 확신 정도

- 선수, 위치, 성공 여부와 슛 종류마다 내부 판단 정도를 가질 수 있습니다.
- 슛 시도와 종류는 확실하지만 성공 장면만 보이지 않으면 슛과 종류는 자동 저장하고 성공 여부만 `판단 불가`로 둡니다.
- Terra와 Sol의 판단이 같은 항목은 자동 확정하고, 서로 다른 항목만 `확인 필요`로 표시합니다.
- 화면에 없는 장면은 리바운드 행동이나 점수 표시가 있을 것이라고 추측하지 않습니다.
- 판단 기준값은 테스트 결과에 따라 조정하며 사용자에게 확실한 척하지 않습니다.

#### 분석 구간 경계

- 사용자가 지정한 시작 시점보다 3초 앞부터 겹쳐 분석합니다.
- 시작 시점 전에 끝난 동작은 저장하지 않고, 시작 시점에 걸쳐 이어진 슛만 현재 구간의 후보로 포함합니다.
- 이 방식으로 구간 시작 직후의 릴리스를 놓치는 일을 줄입니다.

#### 실패 처리

- OpenAI 호출이 실패해도 이미 찾은 슛 후보와 위치를 버리지 않습니다.
- 슛 종류를 `확인 필요`로 두고 사용자가 직접 선택할 수 있게 합니다.
- 선수나 성공 여부를 구분하지 못하면 해당 항목을 `확인 필요`로 둡니다.
- 슛과 종류가 확인됐지만 성공 근거만 없으면 성공 여부만 `판단 불가`로 저장합니다.
- 공을 놓치거나 가림이 심한 구간은 확인하지 못한 항목과 이유를 구분해 남깁니다.

#### 확인 방법

- 성공, 실패, 레이업, 제자리, 풀업이 포함된 개인 영상을 사용합니다.
- OpenAI 연결이 정상인 경우와 실패한 경우를 각각 시험합니다.
- 실패 시 전체 분석이 완료된 것처럼 표시되지 않는지 확인합니다.
- 같은 슛이 중복으로 기록되지 않는지 확인합니다.

### 6.9 슛 검토 목록

#### 화면에 보여줄 항목

- 슛 순서
- 영상 시간
- 선수
- 코트 위치 또는 구역
- 성공·실패
- 슛 종류
- 자동 분석 또는 사용자 확인 상태
- 확인이 필요한 이유

#### 사용자의 행동

- 기록을 눌러 전체 슛 시퀀스를 재생합니다.
- `확인`을 눌러 결과를 그대로 확정합니다.
- 내용을 고쳐 저장합니다.
- 잘못 잡힌 슛을 삭제합니다.
- 빠진 슛을 추가합니다.

#### 정상 결과

- 확인한 기록은 `사용자 확인` 상태로 바뀝니다.
- 검토가 필요한 기록 수를 다시 계산합니다.
- 모든 확인 필요 기록을 처리하면 분석 상태를 `완료`로 바꿀 수 있습니다.
- 확인하지 않은 기록이 남아 있으면 `검토 필요` 상태를 유지합니다.

#### 확인 방법

- 확인 필요 기록을 하나씩 처리할 때 남은 수가 줄어드는지 확인합니다.
- 목록에서 선택한 기록과 재생되는 장면이 같은지 확인합니다.

### 6.10 슛 기록 추가·수정·삭제

#### 슛 추가

사용자는 원본 영상에서 시간을 선택하고 다음 내용을 입력합니다.

- 전체 슛 시퀀스의 시작과 끝
- 선수
- 코트 위치
- 성공 또는 실패
- 슛 종류

저장하면 `사용자 확인` 기록으로 추가합니다.

#### 슛 수정

다음 항목을 바꿀 수 있습니다.

- 선수
- 코트 위치
- 성공·실패
- 슛 종류
- 영상 구간

#### 슛 삭제

- 삭제 전에 확인 메시지를 보여줍니다.
- 확인하면 해당 슛만 삭제하고 영상은 유지합니다.
- 잘못 삭제한 슛의 복구 기능은 첫 버전에 포함하지 않습니다.

#### 수정 후 계산

- 전체 시도 수, 성공 수, 실패 수와 성공률을 다시 계산합니다.
- 선수별 통계를 다시 계산합니다.
- 슛 종류별 통계를 다시 계산합니다.
- 3D 슈팅 맵과 2D 히트맵을 다시 그립니다.

#### 잘못된 입력

- 영상 범위를 벗어난 시간은 저장할 수 없습니다.
- 시작 시간이 끝 시간보다 늦으면 저장할 수 없습니다.
- 코트 밖의 위치는 저장할 수 없습니다.
- 선수, 성공 여부와 슛 종류가 없으면 저장할 수 없습니다.

#### 확인 방법

- 슛 하나를 추가, 수정, 삭제할 때 모든 통계와 두 지도에 즉시 반영되는지 확인합니다.
- 프로그램을 다시 실행해도 수정 결과가 남는지 확인합니다.

### 6.11 분석 결과 요약

#### 전체 결과

- 전체 시도 수
- 성공 수
- 실패 수
- 전체 성공률
- 확인 필요 기록 수
- 슛 종류별 시도 수와 성공률
- 분석 시작 시간과 완료 시간

성공률은 `성공 수 ÷ 시도 수 × 100`으로 계산합니다. 시도 수가 0이면 0%로 단정하지 않고 `기록 없음`으로 표시합니다.

#### 선수별 결과

- 전체 선수 또는 특정 선수를 선택합니다.
- 선택한 선수의 시도 수, 성공 수, 실패 수와 성공률을 보여줍니다.
- 선수 선택을 바꾸면 3D 맵, 히트맵과 기록 목록도 같은 선수 기준으로 다시 계산합니다.

#### 결과 화면 필터

결과 화면 안에서 다음 조건을 선택할 수 있습니다.

- 전체 선수 또는 특정 선수
- 전체 결과, 성공만 또는 실패만
- 전체 슛 종류 또는 특정 슛 종류

필터를 바꾸면 요약 수치, 3D 슈팅 맵, 2D 히트맵과 슛 기록 목록을 같은 조건으로 다시 계산합니다. 이는 저장된 과거 분석을 찾는 검색 기능이 아니라 현재 열어 본 결과를 자세히 보는 기능입니다. 필터를 해제하면 전체 결과로 돌아갑니다.

#### 확인 방법

- 미리 정답을 아는 기록으로 계산 결과를 비교합니다.
- 선수를 바꿀 때 다른 선수의 슛이 섞이지 않는지 확인합니다.
- 성공·실패와 슛 종류 필터를 바꿀 때 네 가지 결과 영역이 같은 조건을 사용하는지 확인합니다.
- 시도 수가 0인 선수에게 `기록 없음`이 표시되는지 확인합니다.

### 6.12 3D 슈팅 맵

#### 화면 표시

- 나무색 반코트 위에 개별 슛을 표시합니다.
- 성공은 초록색 `O`, 실패는 빨간색 `X`로 표시합니다.
- 색을 구분하기 어려워도 O와 X 모양으로 결과를 알 수 있어야 합니다.
- 기본 시점은 코트 전체가 보이는 대각선 시점입니다.

#### 조작

- 마우스를 끌어 시점을 회전합니다.
- 마우스 휠 또는 화면 버튼으로 확대·축소합니다.
- 초기 시점으로 돌아가는 버튼을 제공합니다.
- O/X를 누르면 해당 슛을 선택합니다.

#### 선택 결과

- 선수 이름과 등번호
- 코트 구역
- 성공 또는 실패
- 슛 종류
- 영상 시간
- 사용자 확인 상태
- 전체 슛 시퀀스 재생 버튼

#### 겹치는 슛

- 같은 위치에 여러 슛이 있으면 모두 사라지지 않도록 약간 나누어 표시하거나 묶음 수를 보여줍니다.
- 묶음을 누르면 해당 위치의 슛 목록을 보여줍니다.

#### 확인 방법

- 성공·실패 표시와 실제 데이터가 일치하는지 확인합니다.
- 같은 위치에 여러 슛을 넣어 모두 선택할 수 있는지 확인합니다.
- 선수 선택과 기록 수정 후 지도가 다시 그려지는지 확인합니다.

### 6.13 2D 존별 히트맵

#### 14개 구역

1. 골밑
2. 페인트존 왼쪽
3. 페인트존 중앙
4. 페인트존 오른쪽
5. 왼쪽 베이스라인 미드레인지
6. 왼쪽 윙 미드레인지
7. 정면 미드레인지
8. 오른쪽 윙 미드레인지
9. 오른쪽 베이스라인 미드레인지
10. 왼쪽 코너 3점
11. 왼쪽 윙 3점
12. 정면 3점
13. 오른쪽 윙 3점
14. 오른쪽 코너 3점

코트 선과 구역 경계에 정확히 걸친 슛은 한 가지 고정된 규칙으로 한 구역에만 포함합니다. 같은 좌표가 실행할 때마다 다른 구역으로 바뀌면 안 됩니다.

#### 각 구역에 표시할 값

- 성공 수 / 시도 수
- 구역 성공률
- 전체 슛 중 해당 구역 시도 비율
- 개인 연습용 구역 목표 성공률

#### 색상

- 골밑 목표 80%, 페인트존 목표 60%, 미드레인지 목표 45%, 3점 목표 35%를 사용합니다. 이는 리그 평균이 아닌 이 서비스의 개인 연습용 목표입니다.
- 성공·실패가 정해진 슛이 1개라도 있으면 구역 성공률이 목표 이상일 때 초록, 목표 미만일 때 빨강으로 표시합니다.
- 슛 시도는 있지만 성공·실패가 전부 판단 불가이면 중립색으로 표시합니다.
- 시도 0회는 회색과 `데이터 없음`으로 표시합니다.

색상과 함께 성공 수·시도 수·성공률·목표를 숫자로 표시합니다.

#### 적은 기록

- 1~2회만 있어도 목표 대비 초록·빨강을 표시합니다.
- `데이터 부족`으로 숨기지 않습니다.
- 0회일 때만 `데이터 없음`으로 표시합니다.

#### 구역 선택

- 구역을 누르면 그 구역의 슛만 목록으로 보여줍니다.
- 해당 슛을 선택하면 전체 슛 시퀀스를 재생합니다.
- 이는 결과 화면 안에서 보는 구역 선택이며, 과거 기록 검색 기능은 아닙니다.

#### 확인 방법

- 14개 구역의 경계 좌표를 각각 넣어 올바른 구역에 들어가는지 확인합니다.
- 0회, 1회, 2회와 5회 이상인 경우를 확인합니다.
- 골밑·페인트존·미드레인지·3점에서 목표 이상과 미만의 색과 숫자가 일치하는지 확인합니다.

### 6.14 전체 슛 시퀀스 재생

#### 재생 방식

- 선택한 슛의 자동 시작 시점부터 결과 확인 시점까지 재생합니다.
- 원본이 60fps이면 원본 60fps를 유지합니다.
- 원본이 30fps이면 30fps 그대로 재생합니다.
- 인위적으로 프레임을 만들어 60fps처럼 보이게 하지 않습니다.
- 업로드 MP4의 영상 코덱이 브라우저에서 재생하기 어려우면 원본은 보존하고 같은 fps의 H.264 재생용 사본을 자동으로 준비합니다.
- 분석에는 업로드 원본을 사용하고, 브라우저 재생에만 호환 사본을 사용합니다.

#### 화면 기능

- 재생과 일시 정지
- 처음부터 다시 보기
- 현재 시간과 구간 길이
- 원본 영상에서 이어서 보기
- 기록 수정으로 이동

#### 실패 처리

- 저장된 시작·끝 시간이 잘못되면 기본 구간인 후보 시점 5초 전부터 3초 후까지 재생합니다.
- 원본 파일이 없어 재생할 수 없으면 파일이 없다는 사실을 알리고 재생 성공을 가장하지 않습니다.
- 재생용 변환에 실패하면 다른 MP4를 선택하라는 안내를 표시하고 등록 성공을 가장하지 않습니다.

#### 확인 방법

- 캐치 앤 슛, 풀업과 레이업에서 준비 동작부터 결과까지 포함되는지 확인합니다.
- 영상 처음과 끝에 가까운 슛에서 재생 오류가 없는지 확인합니다.
- 30fps와 60fps 원본을 각각 확인합니다.

### 6.16 영상과 분석 결과 삭제

#### 사용자의 행동

- `영상과 분석 결과 삭제`를 다시 누릅니다.

#### 정상 결과

- 원본 영상 파일을 삭제합니다.
- 코트, 선수, 슛과 통계 정보를 함께 삭제합니다.
- 목록에서 해당 항목을 제거합니다.
- 성공 안내를 보여줍니다.

#### 실패 처리

- 일부 파일을 삭제하지 못하면 전부 삭제된 것처럼 표시하지 않습니다.
- 남아 있는 항목과 다시 시도 방법을 안내합니다.
- 삭제 도중 프로그램이 종료되어도 다음 실행에서 깨진 기록이 정상 결과처럼 보이지 않게 확인합니다.

#### 접근과 복구

- 현재 로컬 사용자만 삭제할 수 있습니다.
- 휴지통 이동 또는 복구는 첫 버전에서 보장하지 않습니다.

#### 확인 방법

- 삭제 취소 시 아무것도 지워지지 않는지 확인합니다.
- 삭제 확인 후 원본과 연결된 모든 결과가 함께 없어지는지 확인합니다.
- 삭제한 항목을 다시 열 수 없는지 확인합니다.

### 6.17 분석 실패와 다시 시도

#### 대표 실패 이유

- 영상 화질이 너무 낮음

- 성공·실패를 판단할 수 없음

- PC 저장 공간 부족
- 프로그램 처리 오류

#### 화면 동작

- 설정을 고칠 수 있으면 해당 화면으로 이동하는 버튼을 제공합니다.

#### 확인 방법

- OpenAI 키가 없거나 잘못된 경우 실제 키를 화면이나 로그에 표시하지 않는지 확인합니다.
- 네트워크를 사용할 수 없는 경우 완료 상태로 바뀌지 않는지 확인합니다.
- 다시 시도 후 중복 슛이 생기지 않는지 확인합니다.

### 6.18 3대3 기능

#### 첫 버전에서 완성할 범위

- 촬영 형태에서 3대3 선택
- 최대 6명의 이름과 등번호 등록
- 정보가 없으면 선수 A~F 사용
- 영상에서 각 선수를 눌러 지정
- 슛마다 슈터 저장
- 전체 또는 선수별 결과 선택
- 잘못 연결된 슈터를 사용자가 수정
- 선수별 3D 맵, 히트맵과 통계 표시

#### 자동 판단 원칙

- 프로그램은 지정한 선수를 영상 안에서 추적합니다.
- 슛 후보마다 가장 가능성 높은 슈터를 연결합니다.
- 선수끼리 가려지거나 추적이 바뀌면 `확인 필요`로 표시합니다.
- 자동 구분이 불확실해도 사용자가 슈터를 직접 선택해 결과를 완성할 수 있어야 합니다.

#### 완료와 테스트의 구분

- 화면, 저장, 선수 지정, 수정과 선수별 결과 흐름은 구현합니다.
- 발표 전 공식 정확도 시험과 MVP 합격 판정은 개인 연습 영상으로 진행합니다.
- 3대3 자동 선수 구분 정확도는 별도 참고 결과로 기록하며 MVP 합격 조건으로 사용하지 않습니다.

#### 확인 방법

- 6명을 등록하고 선수 A~F를 생성할 수 있는지 기능 시험을 합니다.
- 각 선수에게 수동으로 슛을 연결했을 때 선수별 통계가 맞는지 확인합니다.
- 자동 선수 추적 정확도 시험은 개발 결과가 준비되면 별도로 진행합니다.

## 9. 정확도와 성능 확인 기준

### 개인 연습 영상 1차 목표

- 슛 발견률: 실제 슛의 80% 이상
- 성공·실패 판단: 프로그램이 발견한 슛의 85% 이상

이 수치는 지원 촬영 조건을 만족하는 테스트 영상에서 측정하는 개발 목표이며 모든 영상에 대한 보장이 아닙니다.

### 측정 방법

1. 사람이 테스트 영상을 먼저 보고 정답 기록을 만듭니다.
2. 실제 슛 수, 시간, 위치, 성공·실패와 종류를 기록합니다.
3. 프로그램 결과와 정답을 비교합니다.
4. 놓친 슛, 잘못 추가한 슛과 잘못 판단한 항목을 따로 셉니다.
5. 1분과 10분 영상의 처리 시간도 함께 기록합니다.

### 현재 PC 예상 시간

- 1분 영상: 약 2~5분
- 10분 영상: 약 15~40분

실제 결과가 예상과 다르면 실제 측정값을 문서에 기록합니다. 거짓 진행률이나 완료 시간을 표시하지 않습니다.

## 10. 전체 확인 시나리오

### 시나리오 A: 개인 연습 정상 분석

1. 정상적인 1080p MP4를 선택합니다.
2. 개인 연습과 선수 이름을 입력합니다.
3. 동의와 AI 안내를 확인합니다.
4. 코트를 맞추고 분석 시작을 누릅니다.
5. 분석을 완료하고 확인 필요 기록을 검토합니다.
6. 3D 맵, 히트맵과 전체 시퀀스를 확인합니다.
7. 프로그램을 다시 실행해 결과가 남는지 확인합니다.

### 시나리오 B: 잘못된 파일

1. MP4가 아닌 파일, 40분 초과 파일과 5GB 초과 파일을 각각 선택합니다.
2. 정확한 실패 이유가 표시되는지 확인합니다.
3. 분석 기록이 잘못 만들어지지 않는지 확인합니다.

### 시나리오 C: 분석 수정

1. 성공 슛 하나를 실패로 변경합니다.
2. 위치와 슛 종류를 변경합니다.
3. 빠진 슛을 추가하고 잘못된 슛을 삭제합니다.
4. 모든 통계, 3D 맵과 히트맵이 맞게 바뀌는지 확인합니다.

### 시나리오 D: 분석 취소와 재시도

1. 분석 중 취소합니다.
2. 원본은 남고 중간 결과가 제거되는지 확인합니다.
3. 같은 영상으로 다시 분석해 중복 기록 없이 완료되는지 확인합니다.

### 시나리오 E: 3대3 기능

1. 3대3을 선택하고 6명을 등록합니다.
2. 이름·등번호가 없는 선수는 선수 A~F로 만듭니다.
3. 영상 화면에서 각 선수를 지정합니다.
4. 슛의 선수를 수정하고 선수별 결과가 다시 계산되는지 확인합니다.

### 시나리오 F: 삭제

1. 삭제 창에서 취소해 자료가 유지되는지 확인합니다.
2. 다시 삭제하고 원본 영상과 모든 연결 결과가 함께 없어지는지 확인합니다.

## 2026-11-03 구역 판정·도형 경계 통일과 카메라 표시

- 구역 이름과 분류 순서는 기존 백엔드 판정을 유지한다. 프론트의 임의 곡선·사선 대신 백엔드 기준에서 생성한 동일한 좌표 도형을 2D와 3D에 사용한다.
- 3점선은 림 중심 (25, 5.25)에서 반지름 23.75ft, 골밑은 반지름 4ft다. 페인트존은 x=17~33, y=0~19이며 정확히 3등분한다. 미드레인지 베이스라인 경계는 y=13, 정면 미드레인지의 좌우 경계는 x=19·31, 정면 3점의 좌우 경계는 x=17·33이다. 앞선 조건에 속한 구역을 우선 배정한다.
- 원 경계의 언어별 부동소수점 차이를 막기 위해 0.000000001ft 허용 오차만 적용한다. 3점선 위는 3점, 골밑 원 위는 골밑이다. 그림의 원은 4096개 선분으로 근사하며 최대 오차는 0.00001ft 미만이다. 선 위의 마우스 선택은 도형 겹침 순서 대신 같은 좌표 판정으로 결정한다.
- 구역 좌표는 `frontend/src/utils/courtGeometry.json`에 생성해 보관한다. 백엔드 판정 기준을 바꾸면 `backend`에서 `python scripts/generate_court_geometry.py`로 갱신하고 경계 시험을 실행한다. 생성 도구만 `requirements-geometry.txt`가 필요하며 일반 서버 실행에는 필요하지 않다.
- 숫자 마커는 높은 시점(55도 이상)에서 바닥에 눕고, 낮은 시점(10도 이하)에서 세워지며 그 사이는 연속적으로 전환한다. 구역이 올라오면 마커의 바닥 높이도 함께 바뀐다. 마커에 코트가 겹쳐 일부가 잘리지 않도록 표시한다.
- 마커 크기는 기본 1.9ft, 선택 2.2ft다. 기존의 최소 클릭 범위는 유지한다. 첫 시점과 초기 시점은 골대가 정면인 낮은 구도다. 축소 한도는 현재 각도·화면 비율에서 코트 전체가 들어오는 거리의 1.12배로 제한한다.
- 저장된 슛 좌표·득점·종류·구역 및 기존 통계는 이 표시 변경으로 다시 저장하거나 재분석하지 않는다.

## 2026-11-03 구도별 코트 설정과 위치 검증 보완

1. 대표 장면을 고르고 네 모서리·림을 지정한 뒤 확인란을 체크한다. ‘이 구도 저장’은 현재 화면에 남아 구도를 저장하고, 다음 단계 버튼은 저장 후 분석 준비로 이동한다.
2. 다른 대표 장면을 고르면 미저장 점의 지정 상태를 초기화한다. 기존 저장 구도는 삭제되지 않으며 ‘저장한 구도’에서 다시 선택할 수 있다. 같은 시각 저장은 해당 구도만 갱신한다.
3. 선택 3점선은 화면에 보이는 구간만 5~40개 점을 순서대로 찍는다. 45도~45도 부분 선과 코너 직선도 허용한다. 마지막 점을 취소할 수 있다. 화면 밖·중복·실제 선분 교차·너무 짧은 선은 저장하지 않고 오류를 알린다. 끝점 사이를 닫는 가상 선은 만들지 않는다.
4. 영상 특징 대응 뒤 수동 바닥 기준점 주변의 독립 영상 패치가 최소3곳 일치해야 기존 좌표 변환을 옮긴다. 이 영상 검사는 바닥 좌표 정답을 수학적으로 보장하는 기능은 아니다. 사람이 가리거나 식별되지 않으면 보수적으로 위치를 보류할 수 있다.
5. 검증된 화면 변환을 실제 코트 변환에 적용한다. 미검증 구도 또는 환산 발 위치와 AI의 좌우 충돌이 남으면 AI 신뢰도와 무관하게 위치를 비운다. 슛 종류와 득점 결과는 보존한다.
6. 저장한 3점선도 같은 검증 변환으로 옮겨 발 표본과 비교한다. 림의 바닥 투영점에서 발 방향으로 뻗은 선이 실제 지정 선분과 한 곳에서 만날 때만 안/밖을 비교한다. 지정 범위 밖·변환 없음·여러 교차는 추가 판단하지 않는다. 실제 교차점에서6px 이내 또는 AI 판정과 안/밖이 다르면 위치 확인 필요로 남긴다.6px는 초기 보수적 경계값이며 해상도·촬영 조건별 검증이 필요하다. 검출 발 표본은 신발 접촉의 완전한 정답이 아니다.
7. 완료 확인은 복수 구도 저장·새로고침 조회, 이전 구도 보존, 잘못된 배경 대응 차단, 실제 보정 적용, 좌우·3점선 충돌 보존을 각각 테스트한다. 실제 영상 위치 판정은 사용자 기준점과 정답을 대조한다.

8. 사람 탐지 상자의 아래쪽 중앙은 발 위치의 근사값이다. 새 후보는 원본 크기·출처·경계 잘림 표시를 보관한다. 화면 경계(2px 또는 짧은 변의0.2% 중 큰 값)에 닿거나 좌우로 잘린 상자는 투영에서 제외한다. 선택한 사전 표본이 잘렸으면 다른 시각의 공중 표본으로 대체하지 않는다. 유효 디딤발이 없으면 그 표본을 이용한3점선 검증도 생략하고 근거 부족 상태를 보관한다. 기존 기록에 원본 크기가 없으면 과거 좌표만으로 잘림 여부를 단정하지 않는다.

- 작업 실행은 저장된 페인트존 변환·화면 기준점만 구도 검증기로 보낸다. 수동3점선은 읽어 적용하지 않는다.3점 구역은 기존 표준 코트 판정과AI의 바닥 위치 해석으로 결정한다.
- 위치·종류·득점 및 기존 통계는 설정 UI 제거로 소급 변경하지 않는다. 바닥 대응 실패·좌우 충돌·발 잘림의 보류 원칙은 유지한다.

### 2026-11-04 14구역 경계 충돌 정책

공유 도형과 동일한 판정식에서 실제 인접 경계29쌍을 추출한다. 같은 거리 영역 내부 구분10쌍에는 기본15cm(비교 시험30cm), XY 신뢰도70% 이상, 검증된 구도와 안정된 접지 시각·실제 신발 이미지2개 이상·거리 근거 일치·접지 근사 환산값과의 일치를 모두 요구한다. 이 조건에서만 원래 XY/신뢰도를 유지하고 이름을 좌표 판정에 맞춘다. 실제 거리 경계19쌍, 오차 범위에 실제 경계가 걸리는 교차점, 명시적인 좌표/실제 거리/구도 불확실성에는 적용하지 않는다. 원래 AI 이름과 경계 진단은 별도 보관한다.

AI의 XY 신뢰도와 구역 이름 신뢰도를 분리한다. 기존 위치 신뢰도와 별도 XY 신뢰도가 충돌하면 낮은 값을 사용한다. 저장 좌표는 분류한 원래 수치를 유지하며 소수점4자리 반올림으로 경계를 건너지 않는다. 기존 기록은 소급 수정하지 않는다. [구현·실제 시험·한계](all-zone-boundaries-2026-11-04.md).

### 2026-11-04 실제 접지 픽셀과 관측 자유투선
