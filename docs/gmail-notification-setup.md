# ShotLog Gmail 결과 알림 설정

2026-11-05 사용자 결정으로 결과 알림을 Gmail 방식으로 전환했다. 발송용 Gmail 한 계정을 서버에 연결하고, 각 회원의 인증된 계정 이메일로 결과와 AI 리포트를 보낸다. 발송 계정 준비 전이므로 실제 수신은 아직 확인하지 않았다.

## 발송용 Gmail 준비

1. 발송에 사용할 Google 계정으로 [Google 계정 보안](https://myaccount.google.com/security)을 연다.
2. ‘Google에 로그인하는 방법’에서 2단계 인증을 켠다.
3. [앱 비밀번호](https://myaccount.google.com/apppasswords)를 열고 앱 이름을 ShotLog로 정해 만든다.
4. 발급된 앱 비밀번호를 backend/.env에 직접 입력한다. 앱 비밀번호와 실제 계정 비밀번호는 채팅·문서·Git에 넣지 않는다.

앱 비밀번호는 2단계 인증이 켜진 계정에서 만들 수 있다. 메뉴를 이용할 수 없는 계정의 제한 사항은 Google 안내에서 확인한다. [Google 공식 안내](https://support.google.com/accounts/answer/185833?hl=ko)

## 서버 설정

backend/.env에 아래 항목을 추가한다. 빈칸에는 발송용 Gmail 주소와 앱 비밀번호를 직접 입력한다.

```dotenv
EMAIL_NOTIFICATIONS_ENABLED=false
GMAIL_SENDER=
GMAIL_APP_PASSWORD=
PUBLIC_APP_URL=
```

GMAIL_SENDER에는 발송용 계정의 전체 이메일 주소를 넣는다. GMAIL_APP_PASSWORD에는 발급된 앱 비밀번호를 넣는다. 화면에서 복사한 앱 비밀번호의 공백은 코드가 제거한다.

두 값 입력을 마친 뒤 EMAIL_NOTIFICATIONS_ENABLED=true로 바꾸고 백엔드를 재시작한다. 현재 코드는 Gmail의 smtp.gmail.com,465번 포트에서 인증서를 검증하는 SSL 연결을 사용한다. [Google SMTP 안내](https://developers.google.com/workspace/gmail/imap/imap-smtp)

PUBLIC_APP_URL은 선택 사항이다. 실제 배포한 HTTPS 서비스 주소를 넣으면 메일에 결과 페이지 링크를 추가한다. 값이 없으면 통계와 리포트 본문을 메일에 담는다. 원본 영상은 ShotLog 분석 기록에서 확인한다. 휴대폰용 공개 링크를 추가할 때는 해당 주소에서 서비스와 Supabase 로그인이 동작하는지도 확인한다.

다른 설치에는 backend에서 가상환경 Python으로 `python -m alembic upgrade head`를 실행한다. 기존 알림 테이블에 이메일 수신 주소를 추가하는20261105_0010 마이그레이션이다. 과거 전화번호 신청은 새로운 이메일 수신 동의로 다시 신청한다.

## 사용 흐름

1. 분석 진행 화면 또는 결과 화면의 ‘이메일 결과 알림’에서 알림 신청을 연다.
2. 표시된 받는 주소를 확인하고 결과·AI 리포트 수신 동의 후 ‘이메일로 받기’를 누른다. 수신 주소는 서버가 회원 계정의 인증된 이메일에서 가져온다.
3. 인증된 이메일이 없으면 내 프로필에서 이메일 등록과 인증을 먼저 마친다.
4. 분석이 끝나고 모든 슛의 위치와 결과가 확정되면 약15초 이내의 다음 대기 검사에서 처리한다. 확인할 기록이 남으면 마지막 확인·저장 후 다시 검사한다.
5. 최신 저장 AI 리포트가 있으면 재사용한다. 필요한 경우 기존 통계 전용 AI 요청으로 리포트를 생성한다. 수동 리포트 생성 중이면 끝날 때까지 대기한다.
6. 생성 후와 발송 직전에 위치·결과·소유자·수신 이메일·기록 지문을 다시 확인한다. 수신 이메일이나 기록이 바뀌면 재신청을 안내한다.

메일에는 전체·성공·실패 수와 성공률, AI 요약·연습 특징·연습 과제 전체, 이전 연습 성공률이 있으면 그 수치를 담는다. 텍스트와 HTML 두 형식을 제공하고 제목·본문의 사용자 입력은 안전하게 처리한다. 공개 주소가 있으면 본인 로그인이 필요한 결과 링크를 추가한다.

## 중복과 실패

신청은 분석별 한 건으로 저장한다. 대기 중에는 취소할 수 있다. 같은 신청의 동시 처리와 재시작 후 재개는 처리권으로 관리한다. 발송 전에 인증이 해제되거나 수신 이메일이 바뀌면 보류한다.

Gmail 인증·수신 거절 등 확실한 실패는 설정을 확인한 뒤 재신청한다. 발송 도중 연결이 끊겨 접수 여부가 불명확하면 발송 여부 확인 상태로 보존한다. 받은편지함·스팸함과 발송 계정을 확인한 뒤 처리한다. 화면의 접수 완료는 SMTP 서버가 메시지를 접수한 상태이며 실제 받은편지함 수신은 따로 확인한다.

## 검증 범위

완료 조건·중복·동시 처리·리포트 생성 중 변경·수신 이메일 변경·미인증 차단·임의 수신 주소 거절·SMTP TLS/인증/수신 거절/타임아웃·HTML/메일 헤더 처리·공개 주소 없는 본문 구성을 가짜 SMTP로 검증했다. 이메일 관련28개, 전체 백엔드687개·프런트51개·타입 검사와 빌드가 통과했다. 실제 Gmail 인증·메일 수신은 발송 계정 설정 후 본인 이메일로 최종 확인한다.


### 실제 발송 확인 · 2026-11-05

Gmail 인증과 최신30슛 분석의 결과·AI 리포트 SMTP 접수를 확인했다. 발송 상태는 accepted이며 재처리 시 중복 발송이 차단됐다. 백엔드 재시작 후에도 상태와 기존 기록이 유지됐다. 받은편지함 도착은 수신 계정에서 추가 확인이 필요하다.

GMAIL_SENDER는 메일을 보내는 계정이다. 받는 주소는 분석 소유 계정의 인증된 이메일이며 발신 계정과 다를 수 있다. 화면의 마스킹된 수신 주소와 내 프로필 이메일을 확인한다.


### PDF 첨부 형식

새 발송부터 메일 본문은 결과 요약만 표시하고 ShotLog-practice-report.pdf를 첨부한다. 14구역2D 히트맵·성적표·중점 연습 구역·AI 연습 과제가 포함된다. 기존 발송 완료 건은 자동 재발송하지 않는다. 저장된 최신 AI 리포트를 사용하면 PDF 변환에 추가 AI 비용이 없다.

서버에는 reportlab을 설치한다. backend/requirements.txt에 포함돼 있다. PDF 검증 테스트에는 backend/requirements-test.txt를 사용한다. Windows는 맑은 고딕을 자동 사용한다. Linux는 NanumGothic.ttf 또는 NotoSansKR-Regular.ttf를 설치하거나 REPORT_FONT_PATH에 사용 허가가 있는 한글 TTF 절대 경로를 지정한다. 예를 들어 Debian 계열은 fonts-nanum 패키지를 설치할 수 있다. 글꼴은 PDF에 포함되며 발송 준비 오류 시 EMAIL_PDF_FAILED를 확인한다. 앱 비밀번호나 수신 이메일을 글꼴 설정에 넣지 않는다.

최신30슛의2페이지 예시는 output/pdf/shotlog-latest-practice-report.pdf다. 실제 PDF 렌더링·관련35개 테스트·프런트 빌드는 확인했고 PDF 첨부 메일의 실제 수신은 다음 발송에서 확인한다.


### 최종 결정 · 한 장 PDF와 히트맵 목표

PDF는 통계·2D 히트맵·중점 연습 구역만 한 장으로 제공한다. 상세 두 번째 페이지와 사용자가 지정한 두 하단 설명 문구는 표시하지 않는다. 웹 공통 히트맵·홈 미리보기·PDF 모두 시도5개 미만은 회색이며5개부터 골밑/페인트존90%, 기타2점50%,3점40% 이상은 초록·미만은 빨강이다. 실제 숫자와 성공률은 시도 수와 무관하게 유지한다. 기존80/60/45/35 목표와1개부터 색상 적용 요구는 이 결정으로 대체한다.


### 결과 화면에서 다시 보내기

연습 리포트 오른쪽 ‘리포트 보내기’를 누르고 표시된 인증 수신 주소와 동의를 확인해 ‘이메일로 보내기’를 누른다. 위치와 결과 확인을 모두 마쳐야 한다. 이미 보낸 분석도 새 요청으로 다시 보낼 수 있으며 접수 후1분은 연속 발송을 막는다. 같은 요청의 통신 재시도는 같은 요청 ID를 사용해 중복 제거한다. 불명확한 발송은 재신청하지 않고 수신 여부부터 확인한다. 추가 마이그레이션20261105_0011을 적용한다.
